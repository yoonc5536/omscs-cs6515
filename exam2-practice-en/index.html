How to write the exam answer

1The design question is a short essay, not a code-writing exercise. Make the grader’s job easy by using the exact three tags below and by making every claim traceable to a step in your algorithm.

(a) Algorithm

State the base case, divide step, recursive call or calls, combine step, and final return. Write in prose paragraphs—not pseudocode—but make the procedure precise enough to implement.

(b) Justification of Correctness

Name the invariant, induction hypothesis, or structural lemma. Cover every case in the combine step and explain why the returned object has exactly the promised property.

(c) Runtime Analysis

Write a recurrence. Tie each recursive term and each nonrecursive term to real work. Solve it and compare it with the brute-force baseline.

Staff priority

Correct > complete > concise. Never omit a correctness case or runtime term to save space. The grading team reads everything.

EXAM FOCUSA polished answer is not the shortest answer. It is the shortest answer that still lets a grader reconstruct the algorithm, verify every correctness case, and reproduce the runtime bound.
30-SECOND RECAPUse the three tags. Prose, not pseudocode. State the base case. Name the invariant or induction hypothesis. Explain every recurrence term. Beat brute force asymptotically.

1.1 · K MERGE

Merge k sorted lists

Problem. You are given k sorted lists, each of length n. Design a divide-and-conquer algorithm that returns the sorted union of all lists.
Key idea. Merge in a balanced tournament. Every element participates in one linear merge per level, and the number of lists halves each round.
a

Algorithm

If there is only one list, return it. Otherwise, pair the lists: the first with the second, the third with the fourth, and so on. If the number of lists is odd, allow the unpaired list to pass unchanged to the next round. Merge every pair with the standard linear MERGE subroutine. Recursively apply the same procedure to the resulting ⌈k/2⌉ sorted lists. Return the single list remaining at the end.

b

Justification of Correctness

We prove by induction on the number of merge rounds that, after every round, each list is sorted and the multiset union of all lists is exactly the multiset union of the original input. The claim is true before the first round because every input list is sorted. During a round, MERGE replaces two sorted lists by one sorted list containing every element of both lists and no other element. An unpaired list is left unchanged. Therefore sortedness is preserved and the overall multiset does not change. By induction, these properties hold after every round. When only one list remains, that list is sorted and contains exactly all input elements, so it is the sorted union.

c

Runtime Analysis

Sequential merging is not balanced: its work is

(2n−1) + (3n−1) + ··· + (kn−1) = Θ(k²n).

Sorting all kn elements instead costs Θ(kn log(kn)). In the pairwise algorithm, round r has approximately k/2ʳ lists, each of length 2ʳn. The next round performs k/2ʳ⁺¹ merges, so its total work is

(k / 2ʳ⁺¹) · 2(2ʳn) = kn.

There are ⌈log₂k⌉ rounds, giving O(kn log k). Equivalently, if the input size parameter is the number of lists, T(k)=T(⌈k/2⌉)+O(kn), which unfolds across O(log k) levels.

EXAM FOCUSDo not say “there are k merges, each linear.” The merged list grows. Either sum the sequential costs explicitly or show why balanced rounds keep each level at kn.
30-SECOND RECAPPair lists, merge each pair, recurse on half as many lists. Correctness follows from MERGE preserving sortedness and elements. Runtime: kn work per round for log k rounds.

1.2 · ONE UNIT APART

Binary search without a sorted array

Problem. Let A[1..n] be an integer array satisfying |A[i]−A[i+1]|≤1 for every 1≤i<n. Let A[1]=x<y=A[n]. Given an integer z with x≤z≤y, find an index j such that A[j]=z.
Key idea: discrete Intermediate Value Theorem. Consecutive entries differ by at most one, so a walk from a value at most z to a value at least z cannot skip the integer z. Sortedness is unnecessary; the boundary invariant is enough.
a

Algorithm

Maintain indices lo and hi with A[lo]≤z≤A[hi], initially lo=1 and hi=n. While lo<hi, let m=⌊(lo+hi)/2⌋. If A[m]=z, return m. If A[m]<z, set lo=m+1; this is valid because A[m+1]≤A[m]+1≤z. If A[m]>z, set hi=m−1; this is valid because A[m−1]≥A[m]−1≥z. When the loop ends, lo=hi; return that index.

b

Justification of Correctness

The invariant A[lo]≤z≤A[hi] holds initially from A[1]=x≤z≤y=A[n]. If the midpoint is below z, the step-size condition gives A[m+1]≤z, while the old upper endpoint still satisfies z≤A[hi]; hence the invariant holds on [m+1,hi]. The argument is symmetric when the midpoint is above z. By the discrete IVT, every interval whose endpoint values bracket z contains an occurrence of z. The interval strictly shrinks, so the process terminates. At termination lo=hi, and the invariant forces A[lo]=z.

c

Runtime Analysis

Each iteration does constant work and discards about half the index interval. Therefore T(n)=T(n/2)+O(1)=O(log n). By the Master Theorem, a=1, b=2, and f(n)=Θ(1)=Θ(n^{log₂1}), so this is the equal case.

StartA=[2,3,4,3,4,5,6], z=5, lo=1, hi=7.
Step 1m=4. Since A[4]=3<5, set lo=5.
Step 2m=⌊(5+7)/2⌋=6. Since A[6]=5, return index 6.
EXAM FOCUSThe crucial sentence is not “binary search works.” It is why the new endpoint still brackets z: A[m]<z ⇒ A[m+1]≤A[m]+1≤z, and symmetrically on the left.
30-SECOND RECAPMaintain endpoint values on opposite sides of z. The one-unit step bound prevents skipping z. Halve the index interval each time: O(log n).

1.3 · CIRCULAR ARRAY

Maximum-sum contiguous subarray with wraparound

Problem. Given a circular array A of integers, find the maximum sum of a contiguous subarray. A subarray may wrap from index n−1 to index 0. At least one entry is positive. For A=[8,−8,9,−9,10,−11,12], the answer is 22, achieved by [12,8,−8,9,−9,10].
Key idea. Make the combine step constant-time by returning more than the final answer. Each call returns the best internal subarray, the best prefix, the best suffix, and the total sum.
a

Algorithm

Define a recursive routine for a contiguous window. It returns four values: opt, the maximum subarray sum entirely inside the window; Si, the maximum sum of a subarray starting at the window’s first entry; Se, the maximum sum of a subarray ending at the window’s last entry; and total, the sum of every entry in the window.

For one element a, return (a,a,a,a) if a>0; otherwise return (0,a,a,a), allowing the empty subarray only for opt. For a larger window, split it in half, recursively obtain (optL,SiL,SeL,totalL) and (optR,SiR,SeR,totalR), then compute:

Si = max(SiL, totalL + SiR)
Se = max(SeR, SeL + totalR)
total = totalL + totalR
opt = max(optL, optR, SeL + SiR)

Run the symmetric minimum-subarray version as well, where “max” becomes “min” and the one-element minimum is the element itself. Let its answer be minSub. Return max(opt, total−minSub).

b

Justification of Correctness

We prove by induction on window length that all four returned quantities are correct. A maximum prefix of the concatenated window either ends inside the left half, giving SiL, or uses all of the left half and a maximum prefix of the right, giving totalL+SiR. Thus the prefix formula is complete; the suffix formula is symmetric. Every maximum non-wrapping subarray lies fully in the left half, fully in the right half, or crosses the split. Every crossing subarray is a suffix of the left followed by a prefix of the right, so the best crossing value is exactly SeL+SiR. The induction hypothesis makes each ingredient correct, proving opt.

For the circular case, any proper wrapping subarray consists of every entry except one contiguous, non-wrapping gap. Maximizing the wrapping sum is therefore equivalent to minimizing the excluded gap, so its value is total−minSub. Comparing this with the best non-wrapping value covers both cases. Because at least one entry is positive, the final maximum is nonempty.

c

Runtime Analysis

Each call makes two recursive calls on halves and performs only constant-time arithmetic in the combine step. Therefore T(n)=2T(n/2)+O(1)=Θ(n) by the Master Theorem because n^{log₂2}=n dominates the constant combine cost. Running both max and min versions changes only the constant factor, so the total remains Θ(n).

Worked example: [5,−3,4,−2]

Left [5,−3]
Si=max(5,5−3)=5
Se=max(−3,5−3)=2
total=2, opt=5
Right [4,−2]
Si=max(4,4−2)=4
Se=max(−2,4−2)=2
total=2, opt=4
Root combine
Si=max(5,2+4)=6
Se=max(2,2+2)=4
total=4, opt=max(5,4,2+4)=6
Circular comparison
minSub=−3
wrap=4−(−3)=7
Answer 7 from [4,−2,5].
EXAM FOCUSThe improvement from O(n log n) to O(n) comes entirely from augmentation: recursive calls return enough boundary information to avoid rescanning during combine.
30-SECOND RECAPReturn (opt, prefix, suffix, total). Crossing = left suffix + right prefix. Circular wrap = total − minimum non-wrapping gap. Two half calls and O(1) combine give Θ(n).

2.4 · CHOOSE THE ALGORITHM

Compare three recurrence designs

Problem. Algorithm A creates five subproblems of half the original size and uses linear-time combine work. Algorithm B creates two subproblems of size n−1 and uses constant-time combine work. Algorithm C creates nine subproblems of size n/3 and uses O(n²) combine work. Give the asymptotic runtime of each and choose the fastest.
AlgorithmRecurrenceBoundReason
A5T(n/2)+O(n)Θ(n^{log₂5})≈Θ(n²·³²)Recursive term dominates linear combine.
B2T(n−1)+O(1)Θ(2ⁿ)The recursion tree doubles at nearly every decrement.
C9T(n/3)+O(n²)Θ(n² log n)log₃9=2, matching the combine exponent.

Choose A. Its exponent is about 2.32, which beats n²log n asymptotically; B is exponential.

2.12 · PRINT PROGRAM

Count the lines

Problem. A function f(n) does the following when n>1: it prints still going, calls f(n/2), and then calls f(n/2) again. How many lines are printed, asymptotically?

Let P(n) be the number of print executions. Then P(n)=2P(n/2)+1. The recursion tree has Θ(n) nodes, or equivalently Master gives Θ(n). Therefore the program prints Θ(n) lines.

2.14 · REMOVE DUPLICATES

Sort, then scan

Problem. Given n elements, possibly with duplicates, remove all duplicate copies in O(n log n) time, leaving exactly one copy of each distinct value.

Solution. Sort the elements with merge sort in O(n log n). Then scan once from left to right, outputting the first element and thereafter outputting an element only when it differs from its immediate predecessor. After sorting, all copies of a value are adjacent; therefore the scan outputs the first copy and rejects exactly the remaining copies. The scan is O(n), so the total is O(n log n)+O(n)=O(n log n).

2.16 · INFINITE ARRAY

Find the finite boundary, then binary search

Problem. An infinite array contains sorted integers in its first n cells and ∞ in every later cell. The value n is unknown. Find a target x in O(log n) time, or report that it is absent.

Solution. Probe indices 1,2,4,8,… until reaching an index 2ʲ whose value is at least x (possibly ∞). If x exists, it must lie between indices 2ʲ⁻¹ and 2ʲ; binary-search that range. Exponential probing uses O(log n) reads because the first power of two beyond the finite prefix is below 2n. The binary search covers a range of size O(n), so it also costs O(log n).

30-SECOND RECAPDoubling finds a search scale without knowing n; binary search finishes inside that scale.

2.17 · FIXED POINT

Find an index equal to its value

Problem. Given a sorted array of n distinct integers A[1..n], decide whether some index i satisfies A[i]=i, in O(log n) time.

Solution. Let m be the midpoint. If A[m]=m, return m. If A[m]<m, search only to the right. Because the integer entries are sorted and distinct, moving one index left decreases the value by at least one; thus, for every i≤m,

A[i] ≤ A[m]−(m−i) < m−(m−i) = i.

So no index at or left of m can be fixed. If A[m]>m, the symmetric argument eliminates the right half. Each step halves the range, giving O(log n).

EXAM FOCUSDistinctness is essential: it creates the “at least one per index” growth needed to discard a whole half.

2.19 · K-WAY MERGE

Sequential versus balanced merging

Problem. You are given k sorted lists of length n. (a) Analyze the complexity of merging them one at a time with MERGE. (b) Give a faster divide-and-conquer method.

Solution. Sequential merging costs (2n−1)+(3n−1)+···+(kn−1)=Θ(k²n). Pairwise tournament merging performs Θ(kn) work per level for Θ(log k) levels, totaling Θ(kn log k). See the complete model answer in Section 1.1.

2.22 · K-TH SMALLEST OF TWO SORTED LISTS

Discard half of the remaining rank

Problem. Two sorted lists have lengths m and n. Design an O(log m+log n) algorithm that returns the k-th smallest element of their multiset union.

Solution. If one list is empty, return the k-th element of the other. If k=1, return the smaller head. Otherwise choose i=min(m,⌊k/2⌋) elements from A and j=k−i from B; if j>n, cap j at n and set i=k−j. Compare A[i] with B[j]. If A[i]≤B[j], none of A[1..i] can be the desired element: at least i+j=k candidates are at most B[j], and the first i elements of A occupy ranks too early. Discard them and search for rank k−i. Otherwise discard B[1..j] and reduce the rank by j. Each step removes about half of the relevant rank, so the time is O(log k)⊆O(log m+log n).

Warmups staff suggested: FastSelect on the concatenation runs in O(m+n); a two-pointer merge also runs in O(m+n). They establish correctness intuition before the logarithmic discard-halves improvement.

2.23 · MAJORITY ELEMENT

Candidate generation plus mandatory verification

Problem. An unordered array A[1..n] permits only equality tests. Decide whether some value occurs more than n/2 times and, if so, return it. Give (a) an O(n log n) divide-and-conquer algorithm and (b) a linear-time improvement.

(a) O(n log n)

Split the array into halves and recursively obtain a possible majority candidate from each half. Count each distinct candidate across the entire current array and return one whose count exceeds half the current length; if neither does, report none. If x is a majority of the whole array, then it must be a majority of at least one half—otherwise its counts in both halves would sum to at most n/2. So it appears among the at most two candidates and the full count finds it. The recurrence is T(n)=2T(n/2)+O(n)=O(n log n).

(b) O(n)

Pair elements arbitrarily. Discard every pair containing two different values; from each equal pair, keep one copy. Recurse on the at most n/2 survivors to obtain a candidate, then count that candidate in the original current array and return it only if it occurs more than half the time. If x was a majority before pairing, then each discarded unequal pair removes at most one x and one non-x, while each equal x-pair contributes one survivor. Thus x remains a majority among survivors. This direction is enough to ensure that a real majority reaches the final candidate. The recurrence T(n)=T(n/2)+O(n) solves to O(n).

EXAM FOCUSOnly one implication is valid: “majority before pairing ⇒ majority after pairing.” The converse is false. Example: [x,y,z,x,u,v], paired as (x,x),(y,z),(u,v), reduces to [x], although x is not a majority of the original. That is exactly why the final count is mandatory.
30-SECOND RECAPD&C may narrow the answer to a constant-size candidate set. A linear verification pass turns a candidate into a correct answer.

ED EXTRA · MODIFIED BINARY SEARCH

Smallest missing natural number

Problem. Given a sorted array of n distinct natural numbers, find the smallest missing natural number in O(log n). For example, [3,4,5] returns 1, and [1,3,4,6] returns 2.

Solution. Use 1-based indexing. Before the first missing value, the sorted distinct natural numbers satisfy A[i]=i; at and after the first gap, A[i]>i. Binary-search for the first index satisfying A[i]>i. Initialize lo=1, hi=n, and answer n+1. While lo≤hi, let m be the midpoint. If A[m]=m, search right by setting lo=m+1. Otherwise record m as the current answer and search left by setting hi=m−1. Return the recorded index; if none was recorded, return n+1. Each step halves the range, so the time is O(log n).

Trace 1[1,3,4,6]: m=2, A[2]=3>2 ⇒ record 2, set hi=1.
Trace 2m=1, A[1]=1 ⇒ set lo=2. The loop ends; return 2.
EXAM FOCUSThe monotone predicate is A[i]>i, not the array values themselves. State why the predicate switches only once.

2.1 · FAST MULTIPLICATION BRIEF / ROTE

Three products instead of four

Problem. Multiply the binary numbers 10011011₂ and 10111010₂ using the divide-and-conquer fast-multiplication algorithm.

Split each 8-bit number into 4-bit halves:

x = 1001₂·2⁴ + 1011₂ = 9·16+11
y = 1011₂·2⁴ + 1010₂ = 11·16+10

Compute only three products: p₂=9·11=99, p₀=11·10=110, and p₁=(9+11)(11+10)−p₂−p₀=20·21−99−110=211. Each multiplication is recursively handled the same way until constant-size numbers. Recombine:

xy = p₂·2⁸ + p₁·2⁴ + p₀
= 99·256 + 211·16 + 110
= 28830₁₀ = 111000010011110₂.

2.27 · Squaring vs. multiplication EXTRA CHALLENGE

Problem. Explore whether a symmetric 2×2 matrix can be squared with five scalar multiplications, whether that gives a recursive matrix-multiplication improvement, and how matrix squaring compares in difficulty with multiplication.

Solution sketch. (a) Symmetry lets a single 2×2 square exploit repeated cross terms, so five scalar multiplications suffice. (b) The naive recursion is invalid: after the first split, the needed subproblems are general products of submatrices, not necessarily squares with the symmetry that saved work. (c) Squaring is as hard as multiplication. One reduction obtains AB+BA from three matrix squarings; a block-matrix construction then isolates AB. Therefore a truly faster general squaring algorithm would imply faster multiplication.

2.28 · Hadamard matrix-vector product EXTRA CHALLENGE

Problem. Multiply the recursively defined Hadamard matrix Hₖ by a vector faster than ordinary dense matrix-vector multiplication.

Solution. Split the vector into equal halves v=(u,w). The block structure of Hₖ gives

Hₖv = ( Hₖ₋₁(u+w), Hₖ₋₁(u−w) ).

Forming u+w and u−w costs O(n), followed by two half-size transforms. Thus T(n)=2T(n/2)+O(n)=O(n log n).

2.32 · Closest pair HARDER; ANALYSIS ABOVE CLASS LEVEL

Problem. Given n points in the plane, find the pair with minimum Euclidean distance using divide and conquer.

Solution overview. Split the points by the median x-coordinate, recursively find the best pair on each side, and let d be the smaller distance. Any better crossing pair must lie in the vertical strip of width 2d centered at the split. Sort strip points by y; for each point, compare it only with the next seven points. The geometric packing fact is that a d×d square contains at most four points from one side when all same-side distances are at least d. If each level sorts its strip, T(n)=2T(n/2)+O(n log n)=O(n log²n). Presorting by y and maintaining the order through recursion reduces combine work to O(n), giving O(n log n).

Recurring patterns cheat sheet

Invariant binary search

State exactly what remains true: A[lo]≤z≤A[hi], or “the first true index lies in [lo,hi].” Prove initialization, preservation, strict shrinking, and what termination implies.

Used by: One Unit Apart, Infinite Array, Fixed Point, smallest missing natural.

Augment the return value

If combine would rescan, ask what summary lets the parent combine in constant time. For maximum subarray, that summary is (opt,prefix,suffix,total).

Used by: Circular Maximum Subarray.

Candidate + verify

Recursion can safely shrink the search to one or two candidates even when it cannot certify them. Finish with a linear count or validation pass.

Used by: Majority Element.

Balanced aggregation

When partial results grow, combine equal-size objects. Then each element is charged once per level and the number of levels is logarithmic.

Used by: K-Way Merge.
