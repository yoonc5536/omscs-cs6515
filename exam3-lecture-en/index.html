1 · GR1 — Strongly Connected Components

1.1 DFS with a clock

Use directed DFS with a clock initialized to 1. When vertex z is first visited, set pre(z)=clock, then increment. After every out-edge of z has been examined, set post(z)=clock, then increment. The clock is assigned exactly twice per vertex, so postorder values lie in [1,2n].

Exam focusConnectivity algorithms here use postorder only. Preorder is a red herring.

1.2 Edge classification and the postorder law

Four edge types

  • Tree: edge used by DFS to discover a vertex.
  • Back: descendant → ancestor.
  • Forward: ancestor → descendant, skipping tree levels.
  • Cross: no ancestor/descendant relation.

Direction of postorder

Along tree, forward, and cross edges, postorder decreases.

Along a back edge, postorder increases because the ancestor finishes after its descendant.

1.3 Cycle iff back edge

This holds for any start vertex and any adjacency-list order. If a cycle exists, take the first cycle vertex visited. Every other cycle vertex is reachable from it and therefore lies in its DFS subtree; the cycle edge entering that first vertex goes descendant → ancestor, so it is a back edge. Conversely, a back edge from descendant a to ancestor b, together with the DFS-tree path b⇢a, forms a directed cycle.

1.4 Topological sort of a DAG

Run DFS and order vertices by decreasing postorder. A DAG has no back edges, and postorder decreases along every remaining edge; therefore every edge points left-to-right in that order. Postorder lies in [1,2n], so counting sort takes O(n); total time is O(n+m).

  • Every DAG has at least one source and one sink.
  • The highest-postorder vertex is a source; the lowest-postorder vertex is a sink.
  • Quiz: X,Y,Z,U,W is valid. There are exactly 3 valid orders: U may occupy any of the last three positions, while Z must precede W.

1.5 SCCs and the metagraph

Vertices v,w are strongly connected iff there is a path v→w and a path w→v. An SCC is a maximal strongly connected set. Collapse each SCC to a metavertex. The resulting metagraph is always a DAG: a metagraph cycle would make every component on that cycle mutually reachable, contradicting maximality because they should have been one larger SCC.

30-second recapEvery directed graph is a DAG of its SCCs. SCC algorithms exploit the source/sink structure of this hidden DAG.

1.6 Kosaraju’s algorithm — model answer

(a)
  1. Build GR by reversing every edge, in O(n+m).
  2. Run directed DFS with a clock on GR and record every post(z).
  3. Order vertices by decreasing postorder, using counting sort.
  4. On the original graph G, run DFS-with-component-number in that order. Start cc=0; whenever the next ordered vertex is unvisited, increment cc and let Explore stamp that number on every vertex it reaches.
(b)

Key fact: the highest-postorder vertex lies in a source SCC. Use the simpler claim: if SCCs S→S′, then max-post(S)>max-post(S′).

Let z be the first vertex of S∪S′ visited. If z∈S′, DFS finishes all of S′ before touching S, because no path returns from S′ to S. If z∈S, it reaches all of both SCCs and is the root that finishes last. Either way the claim holds.

Apply it to GR. Its source SCC is a sink SCC of G; reversing edges does not change SCC membership, only source/sink roles. Exploring from a sink-SCC vertex in G reaches exactly that SCC and nothing outside. Repeating peels SCCs in reverse topological order.

(c)
Reverse graph O(n+m), two DFS runs O(n+m), counting sort O(n). Total: O(n+m).

1.7 Why sink, not source?

Explore from a sink SCC cannot leave it; Explore from a source SCC can reach most or all of the graph, so it cannot isolate the component. This asymmetry forces graph reversal.

False claim“Lowest postorder ⇒ sink SCC” is false for general directed graphs. Let A↔B form SCC {A,B}, let C be alone, and include A→C. DFS from A can produce pre(A)=1, pre(B)=2, post(B)=3, pre(C)=4, post(C)=5, post(A)=6. Lowest postorder is B, yet B lies in the source SCC {A,B}.

1.8 Eight-vertex DFS trace

Start at B and scan adjacency lists alphabetically. Tree edges: B→A, A→D, D→E, E→G, B→C, C→F. Back edges: E→A, F→B. Forward edges: D→G, B→E. Cross edges: F→H, H→G. In the trace, pre(G)=5 and post(G)=6.

1.9 SCC quiz answer

The 12-vertex graph has 5 SCCs: {A}, {B,E}, {C,F,G}, {D}, {H,I,J,K,L}. A reaches many vertices but nothing reaches A. H–L, C/F/G, and B/E are mutually reachable groups. Others reach D, but D reaches nobody.

1.10 Pitfalls

  • Lowest postorder does not identify a sink SCC in a general digraph.
  • A source SCC is useless for peeling because Explore may leave it.
  • Preorder is not used in the SCC algorithm; postorder range is 1..2n.
  • Second-pass components are produced in reverse topological order.
  • Along a back edge, postorder increases in the edge direction.

2 · GR2 — 2-Satisfiability

2.1 Definitions

There are Boolean variables x₁,…,xₙ and 2n literals xᵢ, x̄ᵢ. A clause is an OR of literals; CNF is an AND of clauses. SAT asks for a satisfying assignment or NO. A unit clause has size 1. In k-SAT every clause has size at most k.

Exam focus2-SAT is polynomial-time via SCCs; k-SAT is NP-complete for every k≥3.

2.2 Unit-clause elimination — model answer

(a)
Repeat: choose a unit literal aᵢ; set it True; delete every clause containing aᵢ; remove each occurrence of its complement āᵢ from remaining clauses. A shrunk clause may become the next unit clause. Remember: unit (x̄₁) forces x₁=False.
(b)
Every satisfying assignment must set the only literal in a unit clause True. Deleting clauses already satisfied and deleting occurrences known False preserves satisfaction; reversing these edits extends any reduced-formula solution by the forced assignment.
(c)
O(n+m) with suitable occurrence lists: each variable, clause, and literal occurrence is processed only constantly many times.

Worked example

f=(x₃∨x₂)∧(x̄₁)∧(x₁∨x₄)∧(x̄₄∨x₂)∧(x̄₃∨x̄₄)

  1. (x̄₁) ⇒ x₁=F. Delete that clause; remove x₁: f′=(x₃∨x₂)∧(x₄)∧(x̄₄∨x₂)∧(x̄₃∨x̄₄).
  2. (x₄) ⇒ x₄=T. Remove x̄₄, leaving unit clauses (x₂) and (x̄₃).
  3. x₂=T deletes (x₃∨x₂); x₃=F empties the formula.

One satisfying assignment is x₁=F,x₂=T,x₃=F,x₄=T; direct substitution satisfies all five original clauses.

2.3 Implication graph

Create 2n vertices, one for each literal. Each clause (α∨β) contributes two edges: ᾱ→β and β̄→α. Read the first as “if α is unsatisfied, β must hold.” With m clauses the graph has 2m edges and is built in O(n+m).

2.4 Path semantics

A path xᵢ→x̄ᵢ means xᵢ cannot be True: that choice forces its negation. A path x̄ᵢ→xᵢ means xᵢ cannot be False. If both exist, the literals lie in one SCC and neither truth value works, so the formula is unsatisfiable.

2.5 2-SAT solver — model answer

(a)
  1. Build the implication graph and compute its SCCs.
  2. If any xᵢ and x̄ᵢ share an SCC, output NO.
  3. Otherwise repeatedly take a sink SCC S, set all of its literals True, set the complementary source SCC S̄ False, delete S∪S̄, and continue until empty.
(b)

NO is sound because same-SCC literals force each other in both directions. For the constructive case, use the path-reversal claim: α⇢β exists iff β̄⇢ᾱ exists. Each implication edge has its contrapositive edge, so a path reverses after complementing each literal.

Therefore complements of an SCC form an SCC, and a sink SCC’s complement is a source SCC. Setting sink S True triggers no outgoing implications and pre-satisfies incoming ones. Setting source S̄ False is safe because nothing implies into it; its outgoing implications are vacuous when the tail is False. Each variable’s literals are removed together, so every variable is assigned once and consistently.

(c)
Graph construction O(n+m), SCCs O(n+m), assignment pass touches each vertex and edge once. Total O(n+m).

2.6 Worked implication example

f=(x̄₁∨x̄₂)∧(x₂∨x₃)∧(x̄₁∨x̄₃)

Six vertices and six edges: x₁→x̄₂, x₂→x̄₁, x̄₂→x₃, x̄₃→x₂, x₃→x̄₁, x₁→x̄₃. The highlighted path x₁→x̄₂→x₃→x̄₁ shows that setting x₁=True forces x₁=False. No path leaves x̄₁, so x₁=False remains viable.

2.7 Sink-set-True illustration

Sink S → True

S={x̄₃,x₁} gives x₃=F,x₁=T. No outgoing implication can be triggered outside S.

Complement source S̄ → False

S̄={x₃,x̄₁} is set False, the same consistent assignment. Reverse view: source S′={x₄,x̄₂} set False gives x₄=F,x₂=T.

2.8 Quiz

Problem. Satisfy f=(x̄₁∨x₂∨x̄₃)∧(x̄₂∨x̄₃)∧(x̄₃∨x̄₁)∧(x̄₃), or answer NO.

Answer. x₁=F,x₂=T,x₃=F. Every clause contains at least one True literal.

2.9 Pitfalls

  • Unit (x̄₁) means x₁=False.
  • Delete clauses containing the satisfied literal; delete complement occurrences from the rest—not backwards.
  • The implication direction is ᾱ→β.
  • Set a sink SCC True; an arbitrary SCC is unsafe.
  • The constructive step assumes every xᵢ,x̄ᵢ pair lies in different SCCs.
  • Count 2n vertices and 2m edges. The trick does not generalize to 3-SAT.

3 · GR3 — Minimum Spanning Tree

3.1 Problem and tree facts

Input: an undirected weighted graph G=(V,E) with |V|=n, |E|=m, and edge weights w(e). Output: a spanning tree minimizing Σe∈Tw(e).

  • A tree has exactly n−1 edges.
  • There is exactly one path between every pair of vertices.
  • Connected + n−1 edges ⇒ tree.
  • Adding one edge to a tree creates exactly one cycle.

Greedy chooses a locally optimal next step, but that does not always yield a global optimum—knapsack is the warning example. The central question is which local choices are safe.

3.2 The cut property

Exact statementLet X⊆T for some MST T: X is the partial solution “correct so far.” Let S be a vertex set with no edge of X crossing the cut (S,S̄). Let e* be any minimum-weight edge crossing the cut (ties arbitrary). Then X∪{e*}⊆T′ for some MST T′, possibly different from T.

Slogan: a minimum-weight edge across the cut belongs to some MST.

3.3 Exchange-argument proof

If e*∈T, set T′=T. Otherwise add e*=(a,b) to T. It creates one cycle C: the unique tree path a⇢b plus e*. Since a and b lie on opposite sides, that tree path crosses the cut; choose a crossing edge e′∈T on it. Define

T′ = T ∪ {e*} − {e′}.

  • Tree: one edge added and one removed, so T′ has n−1 edges. Any old T-path that used e′=(c,d) can reroute along C−{e′}, so T′ remains connected; connected + n−1 edges ⇒ tree.
  • Weight: w(T′)=w(T)+w(e*)−w(e′)≤w(T), since e′ also crosses the cut and e* is minimum. Minimality of T forces equality, so T′ is an MST.
  • Preserve X: e′ cannot belong to X because no X edge crosses the cut. Thus X∪{e*}⊆T′.

Corollary in this proof: w(e*)=w(e′); otherwise T′ would be strictly lighter than the MST T.

3.4 Kruskal — model answer

(a)
Sort edges by increasing weight. Set X=∅. Scan each edge e=(v,w): if Union-Find reports find(v)≠find(w), add e to X and union the two components; otherwise skip e because it would create a cycle. Return X.
(b)

Invariant: X⊆ some MST. When adding e*=(v,w) with distinct components, choose S=c(v). Component maximality means no X edge crosses (S,S̄). Sorted order makes e* minimum across that cut: any lighter crossing edge was already scanned and would have joined these components when considered.

The cut property preserves the invariant. At termination X is acyclic and has n−1 edges, hence is a spanning tree; being contained in an MST, it is itself an MST.

(c)
Sorting: O(m log n)=O(m log m). At most m Union-Find operations at O(log n) each: O(m log n). Total O(m log n). Union-Find internals are a black box here.

3.6 Prim from the same lemma

Algorithm: choose a start s, set S={s}, X=∅. Repeat n−1 times: add a minimum-weight edge crossing (S,S̄), then add its outside endpoint to S. With a binary heap, runtime is O(m log n).

Correctness: maintain X⊆ some MST and let S be exactly the vertices spanned by X. No X edge crosses the cut, and Prim chooses the minimum crossing edge, so the cut property preserves the invariant. After n−1 additions, X is a spanning tree contained in an MST.

3.7 Pitfalls

  • Say “some MST,” not “the MST”; ties can yield many MSTs.
  • The weight inequality is non-strict: ≤, then MST minimality forces equality.
  • Prove T′ is a tree, not merely low-weight.
  • Both cut-property hypotheses matter.
  • Cycle test = “same current component”; use Union-Find rather than re-running graph cycle detection.
  • O(m log n)=O(m log m) for simple graphs.

4 · DP3 — Shortest Paths via Dynamic Programming

4.1 Setup and why negative cycles matter

Input: directed graph G with edge weights w(e) and a start vertex s. Define dist(z) as the shortest s→z length. Dijkstra runs in O((n+m)log n) with a min-heap but requires nonnegative/positive edge lengths as assumed in the lecture: it finalizes a vertex and does not later re-explore its outgoing edges when a negative edge reveals a shorter route.

A reachable negative-weight cycle makes shortest walks ill-defined: loop around it k times and the length tends to −∞. The problem becomes: find a reachable negative cycle if one exists; otherwise return all distances.

4.2 Bellman–Ford — model answer

(a)

Define D(i,z) as the shortest s→z path using at most i edges. Base: D(0,s)=0, and D(0,z)=∞ for z≠s.

D(i,z)=min{D(i−1,z), miny:(y,z)∈E[D(i−1,y)+w(y,z)]}

The first term keeps a path with at most i−1 edges. The second uses exactly i edges, trying every possible penultimate vertex y. Iterate i=1..n−1, scanning incoming edges via the reverse graph built once. Return D(n−1,·). For detection, compute row n; any D(n,z)<D(n−1,z) reveals an s-reachable negative cycle.

(b)

Induct on i. An optimal at-most-i-edge path either uses at most i−1 edges, or exactly i edges and ends with some edge y→z. Its prefix must be an optimal at-most-(i−1)-edge s→y path; otherwise splice in a shorter prefix. The recurrence exhausts both cases.

Without a reachable negative cycle, delete every nonnegative cycle from an optimal walk to obtain a simple path of at most n−1 edges. Thus row n−1 is final. If row n improves, an improving n-edge walk repeats a vertex; the repeated segment must contain a negative cycle.

(c)
There are n iterations; each scans all m edges once and performs O(1) relaxation. With O(n+m) preprocessing for the reverse graph, total time is O(nm).
30-second recapCondition on # edges → outer loop n. Condition on the last edge → inner scan m. Therefore O(nm).

4.4 Shortest path vs shortest walk

If changing an edge to a→e=−6 creates cycle b→a→e→b with weights 3+(−6)+2=−1, then a simple s→d path has length 12. One loop produces 5+3−6+2+3+4=11; k loops give 12−k→−∞. The shortest simple path may still be 12, but shortest walk is unbounded.

4.5 Floyd–Warshall — model answer

(a)

Number vertices 1..n. Define D(i,s,t) as the shortest s→t path whose intermediate vertices come only from {1,…,i}. Base: D(0,s,t)=w(s,t) if edge (s,t) exists, otherwise ∞ (and use 0 for s=t under the usual empty-path convention).

D(i,s,t)=min{D(i−1,s,t), D(i−1,s,i)+D(i−1,i,t)}

Either the path avoids vertex i, or it goes through i and splits there into two paths whose intermediates are all in {1,…,i−1}. Return D(n,·,·). A negative diagonal entry D(n,y,y)<0 detects a negative cycle through y.

(b)
Induct on i and split on whether i lies on an optimal path. In the through-i case, both halves are optimal by the splice argument. At i=n all intermediate vertices are allowed. A negative diagonal gives a negative closed walk, which contains a negative simple cycle after deleting nonnegative cycles; a negative cycle conversely yields a negative diagonal.
(c)
Base table: O(n²). Three nested n-loops with O(1) work: O(n³).

Negative-cycle example: triangle a→b→c→a with weights 5, −7, 1 totals −1, so D(n,a,a)=D(n,b,b)=D(n,c,c)=−1.

4.6 Detection scope

Exam focusBellman–Ford finds only negative cycles reachable from its start s. Floyd–Warshall finds a negative cycle anywhere. If edge d→b is flipped to b→d, then BF starting at d cannot reach the a,b,c negative cycle and misses it; FW still detects a negative diagonal.

4.7 All-pairs baseline quiz

Bellman–Ford takes O(nm). Running it from each of n sources takes O(n²m). On dense graphs, m can be Θ(n²), making the baseline O(n⁴), while Floyd–Warshall remains O(n³).

4.8 Arbitrage reduction

Problem. Given exchange rates r(u→v), determine whether a sequence of currency trades returns more than it started with.

  1. Create one vertex per currency and an edge for each permitted exchange.
  2. Set w(u,v)=−ln(r(u→v)).
  3. Run a negative-cycle detector as a black box.
  4. Translate the returned cycle back into the trade sequence.

A cycle is profitable iff ∏r>1, iff ln(∏r)>0, iff Σ(−ln r)<0. Thus arbitrage is equivalent to a negative-weight cycle.

“I’m not expecting you to memorize the names of these algorithms… understand the basic approach… reconstruct the running time… with sufficient time you can reconstruct the actual algorithms.”

4.9 Pitfalls

  • Dijkstra with negative edges is wrong, not merely slower.
  • For “at most i,” do not omit the D(i−1,z) term.
  • Bellman–Ford recurrence scans incoming edges; build the reverse graph once.
  • BF misses s-unreachable cycles; row n is detection-only, while row n−1 gives distances.
  • FW split terms both use i−1.
  • The diagonal test is strictly <0.
  • Distinguish shortest simple paths from unrestricted walks under negative cycles.

5.2 Two greedy correctness templates

GR3 · MST

Safe choice: minimum edge across a cut untouched by X.

Invariant: X is contained in some MST.

Proof engine: exchange—add e*, create a cycle, remove e′ without increasing weight.

GR2 · 2-SAT

Safe choice: sink SCC True paired with complementary source SCC False.

Invariant: remaining implication graph can still be satisfied.

Proof engine: contrapositive path reversal and source/sink complement pairing.

Both proofs identify a local choice, show it extends to a global solution, remove what was settled, and repeat.

5.3 The SCC arc

GR1 builds the tool: Kosaraju computes SCCs in O(n+m). GR2 applies the tool: the implication graph turns 2-SAT into SCC detection and ordering. Build tool, then apply it.

5.4 Reconstruct the DP instead of memorizing it

  • Bellman–Ford: condition on the number of edges → D(i,z); n values of i × m possible last edges → O(nm).
  • Floyd–Warshall: condition on a prefix of allowed intermediate vertices → D(i,s,t); three n-sized dimensions → O(n³).
30-second recapGR1: order SCCs. GR2: assign SCCs. GR3: exchange an edge. DP3: choose the state dimension that makes the last decision local.
