1. DFS 복습 — undirected connected components

DFS(G):                          # G: adjacency list
    visited[*] ← False
    ccnum ← 0
    for v in V (arbitrary order):
        if not visited[v]:
            ccnum ← ccnum + 1
            Explore(v)

Explore(z):
    visited[z] ← True; cc[z] ← ccnum
    for w in adj[z]:
        if not visited[w]: Explore(w)
  • 런타임 O(n + m) (linear time).
  • Path 찾기: 처음 방문할 때 prev[w] ← z를 기록하면 (Dijkstra's의 prev 배열처럼), 같은 component 안의 두 정점 사이 path를 backtracking으로 복원할 수 있다.

2. Directed DFS — pre/postorder

Directed graph에서는 connectivity 정보를 위해 preorder / postorder number를 추가한다. Clock을 1부터 시작:

  • pre(z): 정점 z를 처음 방문할 때의 clock 값 (방문 후 clock++).
  • post(z): z의 탐색을 마칠 때의 clock 값 (기록 후 clock++).

SCC 알고리즘에서는 사실상 postorder만 사용한다.

3. 간선 4종류와 postorder 성질

종류모습postorder
Tree edgeDFS tree 간선 (탐색된 edge)post 감소 (head > tail)
Back edgedescendant → ancestor (위로)post 증가 (유일!)
Forward edgeancestor → descendant (아래로, 여러 칸)post 감소
Cross edge조상-자손 관계 없음 (옆으로)post 감소
핵심: back edge에서만 postorder가 증가한다. 나머지 세 종류(tree, forward, cross)는 모두 postorder가 감소한다.

4. 사이클 ⟺ back edge

Theorem: G에 cycle이 존재 ⟺ DFS tree에 back edge가 존재 (시작 정점·인접 리스트 순서 무관).

  • (⇒) Cycle의 정점 중 가장 먼저 탐색된 정점을 i라 하자. 나머지 cycle 정점들은 모두 i의 subtree에 들어간다. i로 들어오는 cycle edge (i−1 → i)는 descendant → ancestor이므로 back edge.
  • (⇐) Back edge a → b가 있으면, a는 b의 descendant이므로 b에서 a로 내려가는 tree edge 경로 + back edge a → b = cycle.

5. Topological sort — decreasing postorder

DAG(directed acyclic graph)에는 back edge가 없으므로 (§4), 모든 edge에서 postorder가 감소한다. 따라서:

Topological sort: DFS 1회 실행 후 정점을 postorder 내림차순으로 정렬. 모든 edge가 왼쪽 → 오른쪽으로 간다.
  • 정렬이 O(n log n)처럼 보여도 O(n)에 가능: postorder 범위가 1 ~ 2n이므로 크기 2n 배열에 버킷 배치 (counting sort).
  • 총합: DFS O(n+m) + 정렬 O(n) = O(n+m).

6. 퀴즈 — Topological ordering

Q. 5개 정점 그래프의 topological ordering을 하나 쓰고, valid한 ordering이 총 몇 개인지 구하라.

정답: 예) X, Y, Z, U, W. 총 3개 — U를 뒤 3자리 중 아무 데나 둘 수 있고 (3가지), Z는 W 앞에 와야 하므로 나머지는 강제된다.

7. DAG 구조 — source와 sink

  • Source: incoming edge 없음. Sink: outgoing edge 없음.
  • 모든 DAG는 source와 sink를 각각 최소 1개씩 갖는다.
  • 최고 postorder 정점 = source, 최저 postorder 정점 = sink (topological ordering의 맨 앞/맨 뒤).

대안 topo sort: sink를 찾아 맨 뒤에 두고 그래프에서 제거 → 반복. (뒤에서 앞으로 채우기.) 이 아이디어가 SCC 알고리즘으로 이어진다.

8. SCC 정의 + 퀴즈

Strongly connected: v → w 경로와 w → v 경로가 모두 존재.

SCC (strongly connected component): strongly connected인 정점들의 maximal 집합 (더 넣을 수 없을 때까지 확장).

Q. 12개 정점 directed graph의 SCC는 몇 개이며, 각각 무엇인가?

정답: 5개 — {A}, {B, E}, {C, F, G}, {D}, {H, I, J, K, L}.

  • A: A에서 나갈 수는 있지만 A로 들어올 수 없음 → 혼자.
  • D: 들어올 수는 있지만 D에서 나갈 수 없음 → 혼자.

9. Metagraph는 DAG다

각 SCC를 하나의 metavertex로 압축한 metagraph를 만든다. (Component 간 edge가 여러 개면 multigraph가 되지만 무시해도 된다.)

Theorem: Metagraph는 항상 DAG다.

증명 (모순): metagraph에 cycle이 있으면, cycle 위의 두 component S, S′ 사이에 S → S′ 경로와 S′ → S 경로가 있다. S, S′ 내부는 각각 strongly connected이므로 S ∪ S′ 전체가 strongly connected → maximality에 모순. ∎

즉 모든 directed graph는 SCC들의 DAG이며, SCC들을 topological ordering할 수 있다.

SCC metagraph 예시 — DAG이며 왼쪽→오른쪽이 topological ordering.

10. SCC 알고리즘 아이디어 — sink부터 뜯어내기

DAG topo sort의 "sink를 찾아 뒤에 두고 제거"를 SCC에 적용한다: sink SCC를 찾아 출력하고 제거 → 반복. (뒤에서 앞으로 = reverse topological order.)

왜 sink인가: sink SCC 안의 정점 V에서 Explore를 돌리면, sink 밖으로 나갈 방법이 없으므로 정확히 그 component만 방문한다.

왜 source는 안 되나: source SCC의 정점 A에서 Explore하면 A에서 그래프 전체에 도달 가능 → 어떤 정점이 같은 SCC인지 구분 불가.

남은 문제: sink SCC 안에 있는 정점을 어떻게 찾는가?

11. Key fact — lowest는 틀리고, highest는 맞다

DAG에서는 최저 postorder 정점이 sink였다. 일반 directed graph에서도 그럴까?

  • ✗ 반례: A, B가 strongly connected, C는 혼자. A에서 DFS 시작하면 postorder 최저는 B인데, B는 source SCC에 있다 — 정반대!
  • ✓ 참인 명제: 최고 postorder 정점은 항상 source SCC 안에 있다. (어떤 시작 정점·이웃 순서에서도 성립. §13에서 증명.)

우리는 sink SCC 안의 정점이 필요한데, 구할 수 있는 건 source SCC 안의 정점뿐이다. → Reverse graph 트릭:

GR (모든 edge를 뒤집은 그래프)에서:

  • SCC들은 G와 동일 (v⇄w 경로가 뒤집혀도 그대로).
  • Source와 sink가 뒤바뀐다: G의 sink SCC = GR의 source SCC.

∴ GR에서 DFS → 최고 postorder 정점 = GR의 source SCC 안 = G의 sink SCC 안. ✓

12. Kosaraju 알고리즘 (DFS 2회)

Kosaraju(G):                       # directed graph, adjacency list
    1. G^R ← reverse graph of G
    2. DFS on G^R  (postorder 기록)
    3. 정점을 postorder 내림차순으로 정렬
    4. G에서 DFS — 단, undirected connected components 의사코드 그대로
       (ccnum으로 방문 정점에 번호 부여), 정점 순서는 3의 순서대로
    → ccnum이 SCC 번호이며, reverse topological order로 매겨진다

Q. SCC 알고리즘의 런타임은?

정답: O(n + m). Reverse graph 구성 O(n+m) + DFS 2회 O(n+m) + 정렬 O(n) (counting sort).

Kosaraju: 뒤집고 → DFS → 순서대로 다시 DFS. 바닐라 DFS 2회로 SCC + topological order.

13. Key fact 증명 — simpler claim

Simpler claim: SCC S에서 SCC S′로 edge(v ∈ S → w ∈ S′)가 있으면, max postorder(S) > max postorder(S′).

이게 보이면: component들을 max postorder 내림차순으로 정렬하면 모든 edge가 왼쪽→오른쪽 (= topological order), 최고 postorder 정점의 component가 맨 앞 = source SCC. ∎

증명: S ∪ S′에서 가장 먼저 방문된 정점을 z라 하자. S → S′ edge가 있으므로 S′에서 S로 가는 경로는 없다.

  • Case 1: z ∈ S′. z에서 explore하면 S′ 전체는 방문·종료되지만 S는 전혀 건드리지 못한다 (S로 가는 경로가 없으므로). → S′의 모든 postorder < S의 모든 postorder. ✓
  • Case 2: z ∈ S. z에서 S 전체 + v를 거쳐 S′ 전체에 도달 가능하므로, z가 S ∪ S′의 DFS subtree root가 된다. Root가 가장 늦게 끝나므로 z의 postorder가 S ∪ S′ 중 최대 → max(S) > max(S′). ✓

  • Dijkstra's = BFS framework + min-heap (priority queue). 이 수업에서는 항상 min-heap 버전을 쓴다.
  • Edge 길이가 positive여야 한다. Negative가 있으면 DP3의 방법을 참고.

체크리스트

  • Explore 의사코드를 쓰고 O(n+m)을 설명할 수 있다.
  • 간선 4종류와 postorder 성질 (back만 증가)을 말할 수 있다.
  • 사이클 ⟺ back edge를 양방향으로 증명할 수 있다.
  • Topological sort = decreasing postorder, O(n+m) (counting sort).
  • 최고 postorder = source, 최저 postorder = sink (DAG).
  • SCC 정의와 metagraph가 DAG인 이유를 설명할 수 있다.
  • 왜 sink SCC부터 찾는지 (source는 explore가 전체를 방문) 설명할 수 있다.
  • Kosaraju 4단계를 순서대로 쓸 수 있다.
  • Key fact (highest postorder → source SCC)의 증명 아이디어를 말할 수 있다.
