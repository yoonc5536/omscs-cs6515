1. Problem setup — what are we maximizing?

  • A flow network: directed graph G + start vertex source s + end vertex sink t + a capacity ce > 0 on each edge e.
  • Intuition: shipping "supply" from s to t. Internet traffic → capacity = link bandwidth; oil → capacity = pipe capacity.
  • Goal: maximize the amount shipped from s to t without exceeding edge capacities.

2. Formulation — the two constraints of a valid flow

Variables fe = flow along edge e. A valid flow satisfies:

① Capacity constraint: 0 ≤ fe ≤ ce for every edge e. No negative flow, no exceeding capacity.

② Flow conservation: for every vertex v except s and t, flow in = flow out: ∑w→v fwv = ∑v→z fvz. Nothing is created or lost at intermediate vertices.

Size of a flow = total flow out of s = total flow into t. The max-flow problem asks for a valid flow of maximum size.

3. Quiz review — max-flow example

Q. Specify an integer flow value for each edge of the network below to maximize the s → t flow. Order: sa, sb, sc, ad, ae, be, cf, dc, dt, ed, fe, ft.

Quiz example network (flow / capacity). Numbers reconstructed to match the transcript's description.

Answer (flow values): sa=6, sb=1, sc=5, ad=5, ae=1, be=1, cf=7, dc=2, dt=5, ed=2, fe=0, ft=7 — total flow 12.

Why it is maximum — verification

  • Conservation: c: in(5+2)=7 = out 7 ✓ / e: in(1+1)=2 = out 2 ✓ / d: in(5+2)=7 = out(2+5)=7 ✓ / a: in 6 = out(5+1)=6 ✓ / b: in 1 = out 1 ✓ / f: in 7 = out(0+7)=7 ✓.
  • Capacity: every flow ≤ capacity ✓.
  • Optimality: the only edges into t are dt and ft, with total capacity 5+7=12. Flow into t cannot exceed 12, and we achieved 12 — hence maximum.

Exam point: to prove maximality, show the flow equals the total capacity of the edges into t (or out of s).

4. Cycles are OK

The example contains the cycle c → f → e → d → c. Unlike negative cycles in shortest paths, cycles in a flow network keep the problem well-defined.

  • A maximum flow never needs the cycle: one unit arriving at d and looping around the cycle back to d can simply bypass the cycle and leave d directly.
  • We might want part of a cycle, but we can't know which part in advance. Conclusion: cycles are fine.

5. Removing anti-parallel edges

Edges a → b and b → a together are anti-parallel edges. We remove them up front, because adding forward/backward edges to the residual network later would get confusing otherwise.

  • Transformation: split b → a (capacity 3) into a length-2 path b → x → a, where x is a new auxiliary vertex and both edges get capacity 3.
  • The two networks are equivalent — a max-flow solution converts easily in both directions.

Converting anti-parallel edge b → a into a length-2 path via auxiliary vertex x.

6. Naive attempt — why it fails

Toy example (4 vertices: s, a, b, t). Capacities: s→a=10, a→b=10, b→t=10, s→b=7, a→t=7. Max flow is 17 (total capacity out of s = into t = 17).

Naive algorithm:

  1. Initialize flow to 0 everywhere.
  2. Build the available-capacity graph (= capacity − current flow).
  3. Find an s–t path P in it (BFS/DFS, any path).
  4. c(P) = minimum available capacity along P. Augment c(P) units along P.
  5. Repeat until no s–t path remains.

Failure trace: picking P = s → a → b → t gives c(P) = min(10,10,10) = 10. Flows become sa=10, ab=10, bt=10; those edges have zero available capacity, so no s–t path remains. The algorithm stops at flow 10 while the true maximum is 17 — suboptimal!

The flaw: the available-capacity graph doesn't represent everything possible — in particular, there is no way to undo (decrease) flow already sent.

7. Key idea — backward edges

Reverse-engineering the optimum, we want to augment along s → b → a → t. s → b and a → t increase flow, but b → a doesn't exist in the original network.

Pipe/faucet analogy: sending flow a → b opens the faucet. Sending flow b → a closes the faucet — i.e. decreases the a → b flow.

Since a → b currently carries 10, we can "send" up to 10 units b → a (equivalent to reducing a → b by up to 10).

So instead of the available-capacity graph, we need the residual network, containing forward edges (remaining capacity) plus backward edges (flow we can take back).

8. Residual network Gf — definition

The residual network Gf depends on the current flow f. Same vertices; edges depend on f.

For each edge v → w of the original flow network:

  • Forward edge: if there is available capacity (fvw < cvw), add v → w with residual capacity cvw − fvw.
  • Backward edge: if flow is positive (fvw > 0), add the reverse edge w → v with residual capacity fvw. (Sending x units w → v = decreasing v → w flow by x.)

Forward and backward edges can coexist — which is why we removed anti-parallel edges up front (§5).

Residual network of the toy example after round 1. s→a, a→b, b→t have zero residual capacity. The orange dashed b→a is the backward edge (can take back up to 10 of a→b flow). c(P) = min(7, 10, 7) = 7.

Round 2: P = s → b → a → t, c(P) = 7. sb = 7, ab = 10 − 7 = 3, at = 7. Total flow = 10 + 7 = 17 = maximum ✓

9. Ford-Fulkerson algorithm

Ford-Fulkerson(G, s, t):
    f(e) ← 0 for all edges e
    loop:
        build residual network G^f for current flow f
        find an s–t path P in G^f (BFS/DFS)
        if no such path: output f and stop
        c(P) ← minimum residual capacity along P
        augment c(P) units along P:
            forward edge (u,v):  f(u,v) ← f(u,v) + c(P)
            backward edge (u,v): f(v,u) ← f(v,u) − c(P)   # take back flow
        (repeat)

Termination: stop when the residual network has no s–t path. That the resulting flow is a max-flow follows from the Max-flow = Min-cut theorem (proved later).

10. Runtime analysis — O(mC)

⚠ Key assumption: all capacities are integers. The analysis below needs it.

Why the integer assumption matters

  • Each augmentation is c(P) = minimum of residual capacities; with integer capacities, c(P) is an integer.
  • Residual capacities stay integral, so every round increases the flow by at least 1.

Number of rounds ≤ C

Let C = size of the max-flow. Flow grows by ≥ 1 per round → at most C rounds.

Time per round = O(m)

  • Updating the residual network: path P has ≤ n−1 edges → O(n).
  • Finding the s–t path: BFS/DFS in O(n + m); assuming m ≥ n−1 this is O(m).
  • Augmenting along P: bounded by O(m).
  • → O(m) per round dominates.
Total runtime: O(mC) — O(m) per round × at most C rounds.

11. Discussion — pseudo-polynomial and Edmonds-Karp

Pseudo-polynomial

Two unpleasant aspects of O(mC):

  • It needs the integer-capacity assumption.
  • Runtime depends on the output (C, the magnitude of capacities). Ideally it should depend on their log, or be independent of them entirely. (Same situation as Knapsack.)

Edmonds-Karp algorithm (1972)

  • Same paradigm as Ford-Fulkerson, but instead of any s–t path, always take the shortest path (fewest edges) in the residual network — found by BFS (edge weights ignored).
  • The number of rounds is provably at most mn → total runtime O(m²n).
  • Runtime is independent of the max-flow size, and the integer assumption is gone.

State of the art

Orlin (2013) achieves O(mn) — the current best exact max-flow algorithm for general graphs, ~40 years after Edmonds-Karp (1972).
