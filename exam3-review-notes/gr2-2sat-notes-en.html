1. SAT notation

  • Boolean formula: variables x1 … xn take True/False.
  • Literal: positive or negative form of a variable — 2n total (x1, x̄1, x2, x̄2, …). Read x̄ as "x bar" or "x complement".
  • ∧ = AND (looks like an A), ∨ = OR.
  • CNF (conjunctive normal form): AND of clauses. Each clause is an OR of literals, e.g. (x̄3 ∨ x5 ∨ x1 ∨ x2). Satisfying a clause means satisfying at least one of its literals.
  • Any formula can be converted to CNF, but the size may blow up.

2. The SAT problem

Input: a CNF formula f with n variables and m clauses.

Output: a satisfying assignment if one exists, else NO.

3. Quiz — SAT

Q. f = (x̄1 ∨ x2 ∨ x3) ∧ (x̄2 ∨ x3) ∧ (x̄3 ∨ x1) ∧ (x̄3)
Give a satisfying assignment if one exists, else NO.

Answer: x1 = False, x2 = True, x3 = False. (The unit clause (x̄3) forces x3 = False; verify the rest by substitution.)

4. k-SAT — the dichotomy

  • k-SAT: every clause has size at most k.
  • SAT and k-SAT for k ≥ 3 are NP-complete (3-SAT, 4-SAT, …).
  • 2-SAT is solvable in polynomial time — using the SCC algorithm.
Dichotomy: 2-SAT is easy (linear time); 3-SAT and up are NP-complete.

5. Simplifying the input — eliminating unit clauses

Example: (x̄3 ∨ x2) ∧ (x̄1) ∧ (x1 ∨ x4) ∧ (x̄4 ∨ x2) ∧ (x̄3 ∨ x4).

  1. Find a unit clause, e.g. (x̄1). It forces x1 = False.
  2. Set that literal True (x̄1 True = x1 False).
  3. Clauses containing x̄1 are satisfied → delete them. In clauses containing x1, drop the literal: (x1 ∨ x4) → (x4).
  4. Reduced formula f′: f satisfiable ⟺ f′ satisfiable.
  5. Repeat on new unit clauses. End with the empty formula (satisfied) or all clauses of size exactly 2.

∴ From now on assume all clauses have size exactly 2.

6. The implication graph

Convert the logic problem into a graph problem: 2n vertices (one per literal), 2m edges (two per clause):

Clause (α ∨ β) → two implication edges:

  • ᾱ → β: if α is not satisfied, β must be.
  • β̄ → α: if β is not satisfied, α must be.

Example: f = (x̄1 ∨ x̄2) ∧ (x2 ∨ x3) ∧ (x̄3 ∨ x1) → edges: x1→x̄2, x2→x̄1, x̄2→x3, x̄3→x2, x3→x1, x̄1→x̄3.

Implication graph example: each clause (α ∨ β) yields ᾱ→β and β̄→α.

7. The SCC condition — unsatisfiability test

  • Path x1 ⇝ x̄1: setting x1 = True forces x1 = False at the end → contradiction. ∴ x1 cannot be True.
  • Both x1 ⇝ x̄1 and x̄1 ⇝ x1: x1 can be neither True nor False → f is unsatisfiable.

Unsat condition: if for some variable i, xi and x̄i lie in the same SCC, then f is not satisfiable.

Converse: if for every i, xi and x̄i are in different SCCs, then f is satisfiable (the algorithm below constructs a satisfying assignment).

8. The 2-SAT algorithm

Same "peel off a sink" strategy as the GR1 SCC algorithm:

  1. Simplify f (eliminate unit clauses) → all clauses of size 2.
  2. Build the implication graph G and find its SCCs (with topological order).
  3. Take a sink SCC S → set all literals of S to True. (No outgoing edges, so no implications to follow; incoming edges are safe since their tails are already satisfied.)
  4. The complement set S̄ is a source SCC (§9) → set it to False. (No incoming edges to cause trouble; being False means outgoing implications need not be followed.)
  5. Remove S and S̄ (each variable's positive and negative literal disappear together) → repeat. When the graph is empty, the formula is satisfied.
Running time O(n + m): dominated by the SCC computation (linear time).

9. Key fact — complement of a sink is a source

Key fact: if for all i, xi and x̄i are in different SCCs, then S is a sink SCC ⟺ S̄ (the complement set) is a source SCC.

The proof rests on this claim: if there is a path α ⇝ β, there is also a path β̄ ⇝ ᾱ (and vice versa).

Proof sketch of the key fact:

  1. If S is an SCC then S̄ is an SCC: α, β ∈ S strongly connected gives paths α⇝β and β⇝α; applying the claim yields β̄⇝ᾱ and ᾱ⇝β̄, so ᾱ, β̄ are strongly connected too.
  2. If S is a sink SCC then S̄ is a source: no outgoing edge α→β in S means, by the claim, no incoming edge to ᾱ in S̄. ∴ S̄ has no incoming edges = source SCC. (Reverse argument symmetric.)

10. Proof of the claim — reversing a path

Claim: a path α ⇝ β implies a path β̄ ⇝ ᾱ.

Proof: write the path as γ0(=α) → γ1 → … → γl(=β). The edge γ1 → γ2 comes from some clause (γ̄1 ∨ γ2), whose other implication is γ̄2 → γ1. Repeating along the path yields γ̄l ⇝ γ̄0, i.e. β̄ ⇝ ᾱ. ∎

The reverse direction is symmetric. This completes the correctness proof of the linear-time 2-SAT algorithm.

ClauseAn OR of literals. To satisfy a clause, at least one of its literals must be satisfied.
Unit clauseA clause with a single literal. That literal is forced to True.
Satisfying assignmentA variable assignment that makes the formula True.
Satisfiable / UnsatisfiableA satisfying assignment exists / does not exist.

NP-completeThe class of problems believed to have no polynomial-time algorithm. 3-SAT and up are NP-complete.

Implication edgeA logical edge derived from clause (α ∨ β). ᾱ→β means "if α is not satisfied, β must be." Logically equivalent to the clause.

Sink SCCAn SCC with no outgoing edges. The 2-SAT algorithm sets the sink's literals to True.
Source SCCAn SCC with no incoming edges. By the key fact, the complement of a sink SCC is a source.
Complement (S̄)The set of complements of the literals in SCC S. If S is an SCC, so is S̄.
