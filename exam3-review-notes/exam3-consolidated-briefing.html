Fine print worth remembering

  • DFS: visited[] is internal — not accessible after the run. Vertices reachable from the start get ccnum = 1.
  • SCC: the metagraph's first vertex corresponds to all v with ccnum[v] = 1 from the DFS on the original graph — that's how you map results back.
  • Topological Sort & 2-SAT also hand you all outputs of their underlying DFS / SCC runs.
  • Output naming: your own notation is acceptable if clearly defined — but staff's advice is "why re-define it?" Stick to the standard names.
  • Sorting is not a black box. There is no bucket-sort black box (it exists only inside Topological Sort), and pre[]/post[] come with no guaranteed order — the grader may assume a different one than you do. If you need sorted order, describe the approach fully in your own pre/post-processing. (Staff follow-ups)

✍️ How to write solutions

Every graph problem in this course is a reduction:

Problem input
what you're given
→
Modify / build a graph
transform the input, or create a graph that represents it
→
BLACK BOX
unmodified — run it as-is
→
Modify the output
use the black box's outputs, possibly transformed
→
Solution
answer to the original problem
🚫 NO PSEUDOCODE — YOU WILL LOSE A LOT OF POINTS

The rules

  • Use only the approved black boxes — and you must use at least one.
  • Never modify a black box. Re-creating one with modifications counts as modifying it.
  • All graphs are in adjacency list format. You may assume you always have n = |V| and m = |E| for runtime analysis.

The 3 required parts of every solution

(a) Algorithm

  • Describe how, in words — narrative/paragraph form. Bulleted steps are fine; pseudocode is not. (Line-by-line restatement of code as words still counts as pseudocode — watch out for deeply nested bullets.)
  • Any modifications to the input.
  • The black box(es) used: what's passed in, what's used from the output.
  • Any modifications to the output.
  • The final return.

(b) Justification of Correctness

  • Describe why it works, in words (narrative).
  • Not a formal inductive proof — informal justification is OK.
  • Explain how the black boxes solve your problem, and how your input/output changes get you what you want.

(c) Runtime Analysis

  • Analyze all steps in worst-case Big-O — always, in this course.
  • Known black-box runtimes may be asserted without justification; pre/post-processing must be analyzed.
  • Give a final, fully simplified Big-O. If a target runtime is specified, you must meet it; otherwise faster = more credit.
  • Use the tightest bound: an O(n+m) operation stays O(n+m) (don't inflate to O(n²) unless the graph is known dense, e.g. a clique). If the graph is a tree, m = n−1 so it collapses to O(n). Black-box runtimes themselves need not be simplified.

Graph defaults (unless a problem says otherwise): simple graphs (no multi-edges/self-loops), adjacency list format (DPV 3.1.1) — an array of vertices pointing to linked lists of neighbors, indexable by vertex. A graph may be connected or disconnected, directed or undirected, sparse or dense — assume any of these could be true (staff confirmed: you may not assume sparse). Exceptions: MST problems → connected & undirected; flow networks → connected & directed.

Common actions you may state without details (each assumed O(n+m)):

  • "Reverse the edges in the graph."
  • "Create a copy of G and call it GCopy."
  • "Create a copy of G called GEven that only keeps edges with even numbered weights."
  • "Create a copy of G called GK that only keeps vertices with a degree > k."
  • "Create a residual graph of G called Grs that uses the flows from our run of EK."
⚠️ Two traps from the staff follow-ups
  • No instrumenting a black box while it runs. You can't count things "every time DFS encounters a red vertex," and you can't run "BFS but ignoring edges to black vertices." Your work happens before the run (inputs) and after the run (outputs) — never during.
  • No assuming sparse graphs. Worst-case analysis must survive dense graphs (m = O(n²)) unless the problem states otherwise.

Simplifications when connectivity is known

  • Connected (m ≥ n−1):  O(n+m) = O(m+m) = O(m)
  • Clique (m = n(n−1)/2):  O(n+m) = O(n+n²) = O(n²)
⚠️ From the staff follow-ups
  • Degree is not a free O(1) property. Computing a vertex's degree means scanning its adjacency list — only a check like "is out-degree zero?" can short-circuit. Computing in-degrees for all vertices is O(n+m) with a counter array.
  • The single-edge O(n) surprises people. Finding one specific edge (u,v) is not O(1) — the linked list for u may hold up to n neighbors.

Problem 3.5 — Reverse of a Graph

Statement. The reverse of a directed graph G = (V, E) is GR = (V, ER) with ER = {(v, u) : (u, v) ∈ E}. Give a linear-time algorithm for computing the reverse of a graph in adjacency list format.

(a) Algorithm

Initialize an empty graph GR (adjacency list form) on n = |V| vertices. Then, for each u ∈ V, iterate through the neighbors of u; for each neighbor v of u in G, add u as a neighbor of v in GR.

(b) Justification of Correctness

The reverse graph has the same vertices with every edge direction flipped. Adding the directed edge (v, u) for each edge (u, v) accomplishes exactly this.

(c) Runtime Analysis

Creating the new adjacency list takes O(n). Traversing the original graph to reverse all m edges takes O(n+m), with O(1) to add each edge. Total: O(n) + O(n+m) = O(n+m) — linear, as required.

Problem 3.15 — Computopia

Statement. The police department in Computopia has made all streets one-way. The mayor contends there is still a way to drive legally from any intersection to any other intersection; the opposition is not convinced. Determine whether the mayor is right — in linear time.

Part (a) — Is the mayor's claim true?

Algorithm. Model the city as a directed graph G = (V, E): vertices = intersections, directed edges = one-way streets. Run the SCC black box and check whether the returned metagraph has a single vertex (the whole graph is one SCC). If so, report TRUE; otherwise FALSE.

Justification. Inside one SCC there is a path from every vertex to every other vertex — exactly the mayor's claim. If there are ≥ 2 SCCs, there is a sink SCC and a source SCC, and no path leads from the sink SCC back to the source SCC.

Runtime. Building the graph is O(n+m); SCC is O(n+m); checking the metagraph's vertex count is O(1). Total O(n+m) — linear, as required.

Part (b) — The weaker claim about town hall

Claim. Starting from town hall, wherever you can reach, you can always drive back to town hall.

Algorithm. Model and run SCC as in (a). The claim holds iff the SCC containing town hall is a sink SCC: check the metagraph for outgoing edges from the SCC labeled ccnum[town hall]. TRUE iff there are none.

Justification. If town hall's SCC S is a sink, then within S the town hall reaches every intersection and is reachable back from each of them — and nothing reachable lies outside S. If S is not a sink, some edge leaves S, and the intersections beyond it can be reached from town hall but cannot return.

Runtime. O(n+m) for the model + SCC; the sink check via ccnum[town hall] is O(1). Total O(n+m).

Problem 4.14 — Shortest Path Through a Given Vertex

Statement. You are given a strongly connected directed graph G = (V, E) with positive edge weights and a particular node v0 ∈ V. Give an efficient algorithm for finding shortest paths between all pairs of nodes, with the restriction that these paths must all pass through v0.

(a) Algorithm

Run Dijkstra's from v0 on G, giving distances from v0 to all vertices. Reverse the graph (O(n+m)) and run Dijkstra's from v0 on GR — those distances are the distances to v0 from every vertex in the original graph. For any pair (u, w), the shortest u ⇝ w distance through v0 is distR[u] + dist[w]; an actual path u ⇝ v0 ⇝ w is recovered from the prev[] arrays of the two runs.

(b) Justification of Correctness

Strong connectivity guarantees the paths exist. Any path through v0 splits into a u ⇝ v0 part and a v0 ⇝ w part, each of which must itself be shortest (else the whole improves). Dijkstra's on G finds the best second part; reversing every edge turns "distance to v0" into "distance from v0" in GR, so the second Dijkstra run finds the best first part.

(c) Runtime Analysis

Each Dijkstra run is O((n+m) log n), which simplifies to O(m log n) since the graph is strongly connected; reversing is O(n+m). Producing the dist[]/prev[] structures: O(m log n). (Enumerating all pairs from them costs O(n²) for distances, O(n³) if every path is also reconstructed.)

Problem 7.17 — Bottleneck Edges

Parts (a) & (b) — Max flow, min cut, residual

From the residual graph (figures in the PDF): vertices reachable from s are {s, a, b}; vertices that can reach t are {c, t}. The min st-cut ({s,a,b} | rest) has capacity 11 = 4 + 2 + 2 + 3, matching the max-flow value.

Part (c) — Bottleneck edges

A directed edge (u, v) is a bottleneck edge if increasing its capacity increases the max-flow value. This network has exactly two: (a, c) and (b, c).

Part (d) — A network with no bottleneck edges

The official solution gives a 4-vertex example (figure in the PDF). Alternatively: in this very network, reducing the capacity of (c, t) from 9 to 6 leaves no bottleneck edges.

Part (e) — Algorithm: find all bottleneck edges

Algorithm. (1) Find a max flow f with Ford-Fulkerson. (2) Build the residual graph Gf. (3) Build the reverse of Gf, call it Gr. (4) DFS on Gf from s → ccnum_S[] (vertices reachable from s). (5) DFS on Gr from t → ccnum_T[] (vertices that can reach t in Gf). (6) For each directed edge (v, w) ∈ E, output it as a bottleneck edge iff ccnum_S[v] = 1 and ccnum_T[w] = 1.

Correctness. Increasing c(v, w) raises the max flow iff there is a residual path s ⇝ v and a residual path w ⇝ t: then extra flow can travel s ⇝ v → w ⇝ t. If the two paths share edges, the joined walk contains cycles; dropping them still yields an s–t path through (v, w) — for if a dropped cycle contained (v, w) itself, the remaining walk would be an augmenting path avoiding (v, w), contradicting the maximality of f.

Runtime. Steps 2–6 are each O(n+m); the total is dominated by the max-flow computation: O(mC) with Ford-Fulkerson, or O(nm²) if Edmonds-Karp is used in step 1.

Problem 7.19 — Verifying a Max Flow

Statement. Given a flow network G = (V, E) and a flow f, verify whether f is a valid max flow — in linear time.

(a) Algorithm

First check validity: (i) capacities — 0 ≤ f(e) ≤ c(e) for every edge e; (ii) conservation — for every u ∉ {s, t}, total inflow equals total outflow. If either fails, return FALSE. Then check maximality: build the residual graph Gf and run BFS from s; if t is reachable there is an augmenting path and f is not maximum; if t is unreachable, f is maximum.

(b) Correctness

f is a maximum flow iff there is no augmenting s–t path in the residual graph (the Ford-Fulkerson optimality condition) — exactly what the BFS tests, on top of the definitional validity checks.

(c) Runtime

Validity checks are O(n+m); building Gf is O(n+m); BFS on it is O(n+m). Total O(n+m) — linear, as required.

P1 — Red/Blue Edges: Fewest Red, Then Fewest Blue

Statement. You are given an undirected graph G = (V, E) in which every edge is colored red or blue, its color accessible through col() in O(1) time, and two vertices s, t ∈ V. Design an algorithm that finds, among all paths from s to t with the minimum number of red edges, one with the minimum number of blue edges.

(a) Algorithm

Create a list of edge weights: for each edge e, set w(e) = m + 1 if col(e) = red, and w(e) = 1 if col(e) = blue (reading each color costs O(1)). Run Dijkstra's algorithm from s with these weights, and return the s–t path reconstructed from prev[] (reporting "no path" if dist[t] = ∞).

(b) Justification of Correctness

For any s–t path P with r red edges and b blue edges, its total weight is (m+1)·r + b. Since any simple path has b ≤ m, comparing two paths' total weights compares r first: a path with fewer red edges always wins, regardless of blue counts; among equal r, the smaller b wins. So the minimum-weight path — which Dijkstra's finds, all weights being non-negative — is exactly a path with the fewest red edges and, subject to that, the fewest blue edges.

(c) Runtime Analysis

Building the weight list is O(m) (one O(1) col() call per edge). Dijkstra's runs in O((n+m) log n). Reconstructing the path from prev[] is O(n). Total: O((n+m) log n).

P2 — Max Flow After Adding One Unit-Capacity Edge

Statement. Let {G = (V, E); s, t ∈ V; c(e), e ∈ E} be a flow network where every edge has capacity one. Let f* be a max flow with integer flow values. An edge e ∉ E is added to the network, also with capacity one. Design an algorithm to construct a max flow for the new network, faster than building the flow from scratch.

(a) Algorithm

Keep f* — it is still a valid flow in the new network, since only an edge was added. Create the residual graph of the new network with respect to f* ("Create a residual graph of G called Grs that uses the flows from f*"). Run DFS (or BFS) from s on Grs. If t is reachable, take the resulting s–t path and augment f* by 1 along it (using the new edge's flow and the residual edges as directed); the result is a max flow of the new network. If t is not reachable, f* is already a max flow of the new network.

(b) Justification of Correctness

Adding one edge of capacity 1 can raise the max-flow value by at most 1: any flow in the new network, with the new edge's flow (≤ 1) removed, is a flow in the old network, hence has value ≤ |f*| + 1. So if an augmenting path exists, one augmentation of 1 unit (every residual capacity here is 0 or 1, so the bottleneck is 1) achieves the largest possible value; if none exists, f* satisfies the no-augmenting-path optimality condition in the new network and is maximum.

(c) Runtime Analysis

Creating the residual graph is O(n+m); the DFS/BFS is O(n+m); augmenting along one path is O(n). Total O(n+m) — versus Ω(mC) to rebuild with Ford-Fulkerson from scratch.

P3 — A Spanning Tree Where Every Vertex of U Is a Leaf

Statement. Let G = (V, E) be an undirected, connected, weighted graph, and let U ⊆ V be a nonempty subset of vertices. Design an algorithm that outputs a spanning tree T such that the vertices in U are leaves of T. (Assume such a tree exists.)

(a) Algorithm

Let M = 1 + Σe |w(e)|, a constant larger than the total weight variation of any spanning tree. Create a modified weight list w′: for each edge e, set w′(e) = w(e) + M if e has at least one endpoint in U, and w′(e) = w(e) otherwise. Run Kruskal's algorithm on G with weights w′, and output the returned edges[] as T.

(b) Justification of Correctness

Every vertex u ∈ U needs at least one incident edge in any spanning tree, so every spanning tree has at least |U| edges incident to U — and a tree in which each u is a leaf, and no edge joins two U vertices, has exactly |U| such edges. Because each U-incident edge costs an extra M — more than all ordinary weights combined — minimizing the w′-weight first minimizes the number of U-incident edges. By assumption some spanning tree achieves |U|, so the minimum-w′ tree T also has exactly |U| U-incident edges: each u ∈ U is incident to exactly one edge of T, i.e. u is a leaf (and no U–U edge is used). Kruskal's returns a minimum spanning tree with respect to w′, so T has the required property.

(c) Runtime Analysis

Computing M and the w′ list is O(m). Kruskal's runs in O(m log n). Total: O(m log n).

P4 — Does a DAG Have a Path Visiting Every Vertex?

Statement. Given a directed, acyclic graph G = (V, E), design an algorithm to check whether there exists a path that visits every vertex.

(a) Algorithm

Run the Topological Sort black box to obtain order[] — the vertices v1, …, vn in topological order. Create a list pos[] giving each vertex its position in this order (pos[vi] = i), and a boolean list covered[] initialized to false. Iterate through all edges (u, w) of G: if pos[w] = pos[u] + 1, set covered[u] = true. Finally, check whether covered[vi] is true for every i = 1, …, n−1. Return TRUE if all are covered, else FALSE.

(b) Justification of Correctness

If a Hamiltonian path exists, it lists the vertices in an order consistent with every edge, so it is a topological ordering — and in fact the unique one: the path's own edges chain all n vertices into a total order that every topological ordering must respect. Hence the black box's order[] equals that path, and every consecutive pair is joined by a path edge, so all covered[] checks pass. Conversely, if all consecutive pairs (vi, vi+1) are edges of G, then v1 → v2 → … → vn is itself a path visiting every vertex.

(c) Runtime Analysis

Topological Sort is O(n+m). Building pos[] is O(n), the single pass over all edges is O(n+m), and the final check is O(n). Total: O(n+m).

P5 — Growing Circles: Which Color Wins?

Statement. We are given n points in the plane. Each point is the center of a dynamically changing circle: at time t, each circle has radius t. When two circles touch, their centers are connected. Initially, point s is painted blue and point t is painted red; the rest are unpainted. When an unpainted point is connected to s or t, it gets that color, and remains painted forever. Design an algorithm to decide which color is in the majority once all points are painted. You may assume no point is connected to both s and t at the exact same time.

(a) Algorithm

Create the complete graph on the n points, with edge weights equal to Euclidean distances. Run Prim's algorithm to obtain a minimum spanning tree T, and build T's adjacency list from the returned prev[] (each vertex except the start contributes the edge to its parent, with its weight). Then traverse T from s (a DFS over the tree), computing for every vertex v the value A[v] = the maximum edge weight on the path from s to v in T, by carrying the running maximum across each tree edge. Repeat the traversal from t to compute B[v]. Finally, count the vertices with A[v] < B[v] (these end blue) and those with A[v] > B[v] (these end red), and report the larger color (or a tie).

(b) Justification of Correctness

Centers i and j become connected at time d(i, j)/2, so components merge over time exactly as in Kruskal's algorithm on the complete graph: at any moment, the components are those of the graph of pairs with distance ≤ 2t. By the minimax property of the MST, two vertices become connected at the same time in the complete graph as in T, and the time v's component first merges with the component containing s is A[v]/2, with the component containing t is B[v]/2. A point's component takes the color of the first painted component it merges with — unpainted mergers only delay, never change, which of s or t is reached first in merge order. Since no point connects to both at the same instant, A[v] ≠ B[v] at every deciding comparison, so v ends blue iff A[v] < B[v]. Counting these gives the majority color.

(c) Runtime Analysis

The complete graph has m = n(n−1)/2 = O(n²) edges, so Prim's costs O(m log n) = O(n² log n) — the dominant step. Building T's adjacency list is O(n); each tree traversal touches n−1 edges, O(n); the final count is O(n). Total: O(n² log n).
