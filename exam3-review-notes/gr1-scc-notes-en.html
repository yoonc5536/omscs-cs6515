1. DFS review — undirected connected components

DFS(G):                          # G: adjacency list
    visited[*] ← False
    ccnum ← 0
    for v in V (arbitrary order):
        if not visited[v]:
            ccnum ← ccnum + 1
            Explore(v)

Explore(z):
    visited[z] ← True; cc[z] ← ccnum
    for w in adj[z]:
        if not visited[w]: Explore(w)
  • Running time O(n + m) (linear time).
  • Finding paths: record prev[w] ← z on first visit (like Dijkstra's prev array); backtracking recovers a path between two vertices in the same component.

2. Directed DFS — pre/postorder numbers

Directed graphs need extra info: preorder / postorder numbers. Add a clock starting at 1:

  • pre(z): clock value when z is first visited (then clock++).
  • post(z): clock value when z's exploration finishes (then clock++).

For the SCC algorithm we effectively only use postorder.

3. Four edge types and postorder behavior

TypeShapePostorder
Tree edgeExplored DFS-tree edgedecreases (head > tail)
Back edgedescendant → ancestor (up)increases (only one!)
Forward edgeancestor → descendant (down, multi-level)decreases
Cross edgeno ancestor–descendant relation (sideways)decreases
Key: postorder increases only on back edges. On tree, forward, and cross edges it decreases.

4. Cycle ⟺ back edge

Theorem: G has a cycle ⟺ the DFS tree has a back edge (regardless of start vertex and adjacency-list order).

  • (⇒) Let i be the first vertex of the cycle explored. All other cycle vertices land in i's subtree. The cycle edge into i (i−1 → i) is descendant → ancestor, hence a back edge.
  • (⇐) A back edge a → b plus the tree path b ⇝ a forms a cycle.

5. Topological sort — decreasing postorder

A DAG (directed acyclic graph) has no back edges (§4), so postorder decreases along every edge. Hence:

Topological sort: run DFS once, order vertices by decreasing postorder. All edges go left → right.
  • Sorting looks like O(n log n) but is O(n): postorder numbers range over 1..2n, so bucket them into a size-2n array (counting sort).
  • Total: DFS O(n+m) + sorting O(n) = O(n+m).

6. Quiz — topological ordering

Q. Give a topological ordering of the 5-vertex graph, and count the valid orderings.

Answer: e.g. X, Y, Z, U, W. 3 valid orderings — U can go in any of the last three positions, then Z-before-W forces the rest.

7. DAG structure — sources and sinks

  • Source: no incoming edges. Sink: no outgoing edges.
  • Every DAG has at least one source and at least one sink.
  • Highest postorder vertex = source, lowest postorder vertex = sink (first/last of the topological ordering).

Alternative topo sort: find a sink, place it last, delete it, repeat (fill right to left). This idea leads to the SCC algorithm.

8. SCC definition + quiz

Strongly connected: paths v ⇝ w and w ⇝ v both exist.

SCC (strongly connected component): a maximal set of strongly connected vertices.

Q. How many SCCs in the 12-vertex directed graph, and what are they?

Answer: 5 — {A}, {B, E}, {C, F, G}, {D}, {H, I, J, K, L}.

  • A: can reach others but nothing reaches A → alone.
  • D: reachable but reaches nothing → alone.

9. The metagraph is a DAG

Compress each SCC into a metavertex to form the metagraph (duplicate edges between components may be dropped).

Theorem: The metagraph is always a DAG.

Proof (contradiction): a cycle through S and S′ gives paths S ⇝ S′ and S′ ⇝ S. Since each component is internally strongly connected, S ∪ S′ is strongly connected — contradicting maximality. ∎

Every directed graph is a DAG of its SCCs, which can be topologically ordered.

SCC metagraph example — a DAG; left → right is a topological ordering.

10. SCC algorithm idea — peel off sink components

Apply the DAG idea ("find a sink, place it last, delete") to SCCs: find a sink SCC, output it, delete it, repeat (reverse topological order).

Why sinks: Explore from a vertex V inside a sink SCC visits exactly that component — nothing else is reachable from a sink.

Why not sources: Explore from a source vertex (e.g. A) reaches the whole graph — no way to tell which vertices belong to the SCC.

Remaining problem: how to find a vertex guaranteed to lie in a sink SCC?

11. Key fact — lowest fails, highest works

In a DAG the lowest-postorder vertex is a sink. Does that hold for general directed graphs?

  • ✗ Counterexample: A, B strongly connected; C alone. DFS from A gives B the lowest postorder, but B lies in a source SCC — the opposite!
  • ✓ True fact: the highest-postorder vertex always lies in a source SCC (for any start vertex and neighbor order; proved in §13).

We need a sink-SCC vertex but can only find a source-SCC vertex. → Reverse-graph trick:

In GR (all edges flipped):

  • SCCs are the same as in G (v⇄w paths survive reversal).
  • Sources and sinks swap: sink SCC of G = source SCC of GR.

∴ DFS on GR → highest-postorder vertex lies in a source SCC of GR = a sink SCC of G. ✓

12. Kosaraju's algorithm (two DFS runs)

Kosaraju(G):                       # directed graph, adjacency list
    1. G^R ← reverse graph of G
    2. DFS on G^R  (record postorder)
    3. order vertices by decreasing postorder
    4. DFS on G using the undirected connected-components pseudocode
       (label visited vertices with ccnum), visiting vertices in the order from step 3
    → ccnum labels the SCCs, numbered in reverse topological order

Q. Running time of the SCC algorithm?

Answer: O(n + m). Reverse graph O(n+m) + two DFS runs O(n+m) + O(n) sort (counting sort).

Kosaraju: reverse → DFS → DFS again in that order. Two vanilla DFS runs give SCCs + topological order.

13. Proof of the key fact — simpler claim

Simpler claim: if an edge goes from SCC S to SCC S′ (v ∈ S → w ∈ S′), then max postorder(S) > max postorder(S′).

This gives a topological sort of SCCs by max postorder (decreasing), so the component of the highest-postorder vertex comes first = a source SCC. ∎

Proof: let z be the first vertex of S ∪ S′ visited. The edge S → S′ means no path S′ ⇝ S.

  • Case 1: z ∈ S′. Explore from z visits and finishes all of S′ but never touches S (no path back). → every postorder in S′ < every postorder in S. ✓
  • Case 2: z ∈ S. z reaches all of S and, via v, all of S′, so z roots the DFS subtree of S ∪ S′ and finishes last → max postorder of S ∪ S′ is z ∈ S. ✓

Glossary

TermMeaning
DFS (depth-first search)Graph traversal that goes as deep as possible before backtracking. Runs in O(n+m).
ExploreThe recursive subroutine of DFS: marks z visited and recursively explores its neighbors.
ClockCounter used to assign pre/postorder numbers; starts at 1, incremented on visit and on finish.
Preorder numberClock value when a vertex is first visited.
Postorder numberClock value when a vertex's exploration finishes. The key ingredient of the SCC algorithm.
Tree edgeAn edge actually explored by DFS (edge of the DFS tree/forest). Postorder decreases.
Back edgeEdge from a descendant to an ancestor. The only edge type on which postorder increases. Cycle ⟺ back edge.
Forward edgeEdge from an ancestor down to a descendant (spanning multiple levels). Postorder decreases.
Cross edgeEdge between vertices with no ancestor–descendant relation. Postorder decreases.
DAG (directed acyclic graph)Directed graph with no cycles. Has no back edges; admits a topological sort.
Topological sort / orderingLinear ordering of vertices so all edges go left → right. Obtained from decreasing postorder on a DAG.
Source vertexVertex with no incoming edges. Highest-postorder vertex in a DAG.
Sink vertexVertex with no outgoing edges. Lowest-postorder vertex in a DAG.
Strongly connectedPair of vertices v, w with paths v ⇝ w and w ⇝ v both existing.
SCC (strongly connected component)Maximal set of strongly connected vertices. The directed analog of a connected component.
Metavertex / MetagraphOne SCC compressed into a single vertex / the resulting graph. Always a DAG.
Reverse graph (GR)Graph with all edge directions flipped. Same SCCs; sources and sinks swap.
Kosaraju's algorithmSCC algorithm: DFS on GR → decreasing postorder → DFS on G. Two vanilla DFS runs, O(n+m).
Connected component (ccnum)Set of mutually reachable vertices in an undirected graph. Its labels become SCC labels in Kosaraju's last step.
Ancestor / DescendantA vertex above (explored earlier) / below (explored later) in the DFS tree.
BFS (breadth-first search)Layer-by-layer traversal; computes min-#edges distances from the start plus a prev array. O(n+m).
Dijkstra's algorithmSingle-source shortest paths on positive-weight graphs. BFS + min-heap. O((n+m) log n).
Min-heap (priority queue)Priority queue used by Dijkstra's; O(log n) per operation.
