1. 문제 설정 — 무엇을 maximize하는가

  • Flow network(플로우 네트워크): directed graph(방향 그래프) G + 시작점 source s + 도착점 sink t + 각 edge e마다 capacity(용량) ce > 0.
  • 직관: s에서 t로 "보급품"을 보낸다. 인터넷 트래픽이면 capacity = bandwidth(대역폭), 석유면 capacity = 파이프 용량.
  • 목표: edge 용량을 초과하지 않으면서 s → t로 보낼 수 있는 최대량을 구한다.

2. 정식화 — valid flow의 두 가지 제약

변수 fe = edge e를 따라 흐르는 flow. Valid flow는 다음을 만족한다:

① Capacity constraint(용량 제약): 모든 edge e에 대해 0 ≤ fe ≤ ce. 음수 flow 불가, 용량 초과 불가.

② Flow conservation(유량 보존): s, t를 제외한 모든 vertex v에서 (v로 들어오는 flow) = (v에서 나가는 flow). 즉 ∑w→v fwv = ∑v→z fvz. 중간 정점에서는 flow가 생기거나 사라지지 않는다.

Flow의 size(크기) = s에서 나가는 총 flow = t로 들어오는 총 flow. Max-flow 문제는 valid flow 중 size가 최대인 것을 찾는 것이다.

3. 퀴즈 리뷰 — Max-flow 예제

Q. 아래 flow network에서 각 edge의 flow 값을 정수로 지정해 s → t flow를 maximize하라. 순서: sa, sb, sc, ad, ae, be, cf, dc, dt, ed, fe, ft.

퀴즈 예제 네트워크 (flow / capacity). 트랜스크립트의 설명과 일치하도록 재구성한 수치다.

정답 (flow 값): sa=6, sb=1, sc=5, ad=5, ae=1, be=1, cf=7, dc=2, dt=5, ed=2, fe=0, ft=7 — 총 flow 12.

왜 최대인가 — 검증

  • Conservation 확인: c: in(5+2)=7 = out 7 ✓ / e: in(1+1)=2 = out 2 ✓ / d: in(5+2)=7 = out(2+5)=7 ✓ / a: in 6 = out(5+1)=6 ✓ / b: in 1 = out 1 ✓ / f: in 7 = out(0+7)=7 ✓.
  • Capacity 확인: 모든 flow ≤ capacity ✓.
  • 최적성: t로 들어오는 edge는 dt, ft뿐이고 그 capacity 합이 5+7=12. t로 들어오는 flow는 12를 넘을 수 없는데 12를 달성했으므로 최대다.

시험 포인트: "왜 최대인지"를 물을 때 t로 들어오는(또는 s에서 나가는) edge들의 capacity 합이 달성한 flow와 같으면 그걸로 증명 끝이다.

4. 사이클은 OK

위 예제에 c → f → e → d → c 사이클이 있다. Shortest path 문제에서는 negative cycle이 골칫거리였는데, max-flow에서는 사이클이 있어도 문제가 well-defined하다.

  • 최대 flow는 사이클을 이용하지 않는다: d로 들어온 1 단위를 사이클로 빙빙 돌려 다시 d로 보내는 대신, 그냥 d에서 바로 내보내면 된다 — 사이클을 bypass할 수 있다.
  • 사이클의 일부는 이용할 수도 있지만, 미리 알 수는 없다. 결론: 사이클이 있어도 문제는 잘 정의된다.

5. 역평행 간선(anti-parallel edges) 제거

a → b와 b → a가 동시에 있는 anti-parallel edges는 미리 제거해 둔다. 나중에 residual network를 만들 때 forward/backward edge를 추가하는데, 원래 anti-parallel edge가 있으면 헷갈리기 때문이다.

  • 변환법: b → a (capacity 3)를 길이가 2인 경로 b → x → a로 쪼갠다. x는 새로운 보조 정점(auxiliary vertex), 두 edge의 capacity는 모두 3으로 둔다.
  • 두 네트워크는 equivalent — 한쪽의 max-flow 해를 다른 쪽으로 쉽게 옮길 수 있다.

Anti-parallel edge b → a를 보조 정점 x를 이용해 길이 2 경로로 변환.

6. Naive한 시도 — 왜 실패하는가

Toy example (정점 4개: s, a, b, t). Capacity: s→a=10, a→b=10, b→t=10, s→b=7, a→t=7. 최대 flow는 17이다 (s에서 나가는 capacity 합 = t로 들어오는 capacity 합 = 17).

Naive 알고리즘:

  1. Flow를 0으로 초기화.
  2. Available capacity 그래프(= capacity − 현재 flow)를 만든다.
  3. 그 그래프에서 s–t path P를 찾는다 (BFS/DFS, 아무 path나).
  4. c(P) = P 위 edge들의 available capacity 중 최소값. P를 따라 c(P)만큼 augment.
  5. s–t path가 없을 때까지 2–4 반복.

실패 과정: P = s → a → b → t를 잡으면 c(P) = min(10,10,10) = 10. Flow는 sa=10, ab=10, bt=10이 되고, 세 edge의 available capacity가 0이 되어 s–t path가 사라진다. 알고리즘은 flow 10에서 멈추지만, 실제 최대는 17이다 — suboptimal!

문제점: available capacity 그래프는 "현재 flow에서 할 수 있는 모든 일"을 표현하지 못한다. 특히 이미 보낸 flow를 되돌리는(줄이는) 선택지가 없다.

7. 핵심 아이디어 — 역방향 간선(backward edges)

최적해를 역추적하면, 원하는 augment 경로는 s → b → a → t다. s → b와 a → t는 flow를 늘리지만, b → a는 원래 네트워크에 없는 edge다.

파이프·수도꼭지 비유: a → b로 flow를 보내는 건 수도꼭지를 여는 것. b → a로 flow를 보내는 건 수도꼭지를 잠그는 것, 즉 a → b flow를 줄이는 것이다.

현재 a → b flow가 10이므로, b → a로는 최대 10만큼 "보낼 수" 있다 (a → b를 10만큼 줄이는 것과 동등).

따라서 available capacity 그래프 대신, forward edge(남은 용량) + backward edge(되돌릴 수 있는 flow)를 모두 담은 residual network를 써야 한다.

8. Residual network Gf의 정의

현재 flow f에 대한 residual network Gf: 정점은 그대로, edge는 flow에 따라 정해진다.

원래 flow network의 각 edge v → w에 대해:

  • Forward edge: available capacity가 있으면 (fvw < cvw), 같은 방향 edge v → w를 residual capacity cvw − fvw로 추가.
  • Backward edge: flow가 양수이면 (fvw > 0), 역방향 edge w → v를 residual capacity fvw로 추가. (w → v로 x만큼 보내는 것 = v → w flow를 x만큼 줄이는 것.)

Forward + backward edge가 동시에 존재할 수 있어서, 미리 anti-parallel edge를 제거해 둔 것이다 (§5).

1라운드 후 toy example의 residual network. s→a, a→b, b→t는 residual capacity 0. 주황 점선 b→a는 backward edge (a→b flow 10을 되돌릴 수 있음). c(P) = min(7, 10, 7) = 7.

2라운드: P = s → b → a → t, c(P) = 7. sb = 7, ab = 10 − 7 = 3, at = 7. 총 flow = 10 + 7 = 17 = 최대 ✓

9. Ford-Fulkerson 알고리즘

Ford-Fulkerson(G, s, t):
    모든 edge e에 대해 f(e) ← 0
    loop:
        현재 flow f에 대한 residual network G^f를 만든다
        G^f에서 s–t path P를 찾는다 (BFS/DFS)
        path가 없으면: 현재 flow f를 출력하고 종료
        c(P) ← P 위 edge들의 residual capacity 중 최소값
        P를 따라 c(P)만큼 augment:
            forward edge (u,v):  f(u,v) ← f(u,v) + c(P)
            backward edge (u,v): f(v,u) ← f(v,u) − c(P)   # 역방향으로 되돌림
        (2단계로 돌아가 반복)

종료 조건: residual network에 s–t path가 없으면 멈춘다. 이때의 flow가 max-flow라는 것은 나중에 배울 Max-flow = Min-cut theorem에서 따라 나온다.

10. 런타임 분석 — O(mC)

⚠ 핵심 가정: 모든 capacity가 정수(integer)다. 이 가정 하에서만 아래 런타임 분석이 성립한다.

왜 정수 가정이 필요한가

  • Augment량이 c(P) = residual capacity들의 최소값인데, capacity가 정수면 c(P)도 정수.
  • 따라서 residual network의 capacity가 계속 정수로 유지되고, 매 라운드 flow가 최소 1씩 증가한다.

라운드 수 ≤ C

C = max-flow의 size(찾으려는 값). 매 라운드 최소 1씩 증가하므로 라운드는 최대 C번.

라운드당 시간 = O(m)

  • Residual network 업데이트: augment 경로 P의 길이는 최대 n−1이므로 O(n).
  • s–t path 탐색: BFS/DFS로 O(n + m). m ≥ n−1이라 가정하면 O(m).
  • Augment: 경로를 따라가며 O(m)으로 bound.
  • → 라운드당 O(m)이 dominant.
총 런타임: O(mC) — 라운드당 O(m) × 최대 C 라운드.

11. 심화 논의 — pseudo-polynomial과 Edmonds-Karp

Pseudo-polynomial

O(mC)의 두 가지 문제점:

  • Capacity가 정수라는 가정이 필요하다.
  • 런타임이 출력(C, capacity의 크기)에 의존한다. 이상적으로는 capacity 값 자체가 아니라 그 log에 의존해야 하고, 아예 무관해야 한다. (Knapsack의 상황과 유사.)

Edmonds-Karp 알고리즘 (1972)

  • Ford-Fulkerson과 같은 paradigm. 차이점: residual network에서 아무 s–t path가 아니라 shortest path (edge 수 최소)를 택한다. BFS로 찾는다 (edge 가중치는 무시).
  • 라운드 수가 최대 mn임이 증명된다 → 총 런타임 O(m²n).
  • 런타임이 max-flow size와 무관하고, 정수 가정도 불필요하다.

현재 최고 기록

Orlin (2013)의 알고리즘이 O(mn) — general graph에서 exact max-flow의 현재 최고 기록이다 (Edmonds-Karp 1972로부터 약 40년 만).

알고리즘Path 선택런타임정수 가정
Ford-Fulkerson아무 s–t path (DFS/BFS)O(mC)필요
Edmonds-KarpShortest s–t path (BFS)O(m²n)불필요

체크리스트

  • Valid flow의 두 제약 (capacity, conservation)을 말할 수 있다.
  • Flow size = s의 out-flow = t의 in-flow.
  • 퀴즈 예제에서 flow 12가 최대인 이유를 설명할 수 있다 (t로 들어오는 capacity 합 = 12).
  • Naive 알고리즘이 왜 10에서 멈추는지 설명할 수 있다 (되돌리기 불가).
  • Residual network의 forward/backward edge 정의를 쓸 수 있다.
  • Backward edge의 의미: "수도꼭지 잠그기" = 기존 flow 줄이기.
  • Ford-Fulkerson 6단계를 순서대로 쓸 수 있다.
  • O(mC) 분석: 정수 가정 → 매 라운드 ≥1 증가 → ≤C 라운드 × O(m).
  • Pseudo-polynomial의 의미: 런타임이 capacity 값 자체에 의존.
  • Edmonds-Karp: BFS shortest path, O(m²n), 정수 가정 불필요.
