🔍 Traversal & Structure

The question: "Can I get there? What is the structure of this graph?" These explore and reveal shape — they do not measure distances (except BFS, which does both).

DFS O(n+m)

Go deep first. The exploration tool everything else is built on.

DFS(G):
  for all v in V: visited[v] = false
  clock = 1
  for all v in V: if not visited[v]: Explore(v)

Explore(v):
  visited[v] = true;  pre[v] = clock;  clock++
  for each edge (v, u) in E:
    if not visited[u]: prev[u] = v; Explore(u)
  post[v] = clock;  clock++
Cycle ⟺ back edge. A directed graph has a cycle iff its DFS tree contains a back edge (descendant → ancestor). pre/post numbers classify every edge into tree / forward / back / cross — only back edges increase postorder.

Outputs: ccnum[], prev[], pre[], post[]. Use for: reachability, connected components, cycle detection, and as the engine inside Topological Sort and SCC. Not for: shortest paths — the first path DFS finds is not necessarily the shortest.

Worked examples: GR1 Review Notes — DFS, edge types, cycle test (lecture-based)

Topological Sort O(n+m)

Line up a DAG so every edge points forward.

How: run DFS and list vertices in decreasing postorder — that is the whole algorithm. Post values range over 1..2n, so the sort is a linear counting sort and the total stays O(n+m).

Why it works: in a DAG there are no back edges, so for every edge (u, v), post[u] > post[v] — decreasing postorder puts u before v for every edge. A DAG always has a source (in-degree 0) and a sink (out-degree 0); the first vertex of any topological order is a source, the last is a sink. Output: order[] + all DFS outputs.

Worked examples: GR1 Review Notes — topological sort, quiz, sources and sinks

SCC — Strongly Connected Components O(n+m)

Compress every mutually-reachable cluster into one node — the result is always a DAG.

Kosaraju's algorithm — two DFS runs:

  1. Build the reverse graph GR (flip every edge) — O(n+m).
  2. Run DFS on GR and record postorder numbers.
  3. Run DFS on the original G, starting from the vertex with the highest remaining postorder. Each DFS tree found is exactly one SCC.
  4. Repeat until every vertex is assigned. Outputs: the metagraph + final DFS outputs (ccnum[], …).
Key fact: the vertex with the highest postorder lies in a source SCC of G. That is why the first DFS runs on the reverse graph — processing in decreasing postorder peels off sink SCCs first. (The tempting guess "lowest postorder = sink SCC" is false.)

Using the output: find one vertex's SCC by reading ccnum[v] in O(1). Whole graph strongly connected ⟺ metagraph has a single vertex. Town hall can always return home ⟺ its SCC is a sink SCC.

Worked examples: GR1 Review Notes — SCC quiz, metagraph, Kosaraju, key-fact proof

📏 Shortest Paths

The question: "What is the cheapest / fastest / shortest route?" Pick by the edge weights, and by whether you need one source or all pairs.

Press Next level and watch the queue expand. A vertex is first reached at its shortest distance — that is why BFS computes shortest paths.

Level 0: only s is visited. dist[s] = 0.

BFS O(n+m)

Level by level, with a queue — the first visit is the shortest path.

  1. Mark the source as visited and put it in a queue.
  2. Take the front vertex off the queue.
  3. For each unvisited neighbor, mark it visited and add it to the back of the queue.
  4. Repeat until the queue is empty.

A visited array is essential — cycles would otherwise revisit vertices forever. Vertices leave the queue in order of distance from the source, so the black box returns dist[] (edge count, ∞ if unreachable) and prev[] for path recovery. For a disconnected graph, run BFS from every still-unvisited vertex. BFS vs DFS: BFS goes wide (queue) and guarantees shortest paths in unweighted graphs; DFS goes deep (stack) and does not.

Worked example: GeeksforGeeks — BFS for a Graph (traversal order, disconnected graphs, code)

Dijkstra O((n+m) log n)

Always settle the nearest unvisited vertex — once visited, its distance never changes.

  1. Initialize distances: 0 for the source, ∞ for all others.
  2. Pick the unvisited vertex with the shortest distance as the current vertex.
  3. Relax each unvisited neighbor: if dist[u] + w(u, v) < dist[v], update dist[v].
  4. Mark the current vertex visited — never checked again.
  5. Repeat until all vertices are visited.

Works for directed and undirected graphs with non-negative weights only — negative edges break the greedy choice, use Bellman-Ford instead. The basic version scans all vertices for the minimum (O(n²)); the course version uses a min-heap, O((n+m) log n). The basic version returns distances only; the course black box returns dist[] and prev[] together.

Worked example: W3Schools — Dijkstra's Algorithm (manual run-through from source D)

Bellman-Ford O(nm)

Relax every edge, V−1 times — the patient algorithm that tolerates negative weights.

  1. Initialize distances: 0 for the source, ∞ for all others.
  2. Relax every edge in the graph.
  3. Repeat step 2 V−1 times — a shortest simple path uses at most V−1 edges.
  4. Negative cycle detection: one more round — if any distance still improves, a negative cycle exists.

After k rounds, dist[v] is the best distance using at most k edges — in course notation, iter[k][v]. The black box returns dist[] from iteration n−1, plus iter[][]. Think of negative weights as "cheapest path": an edge of −3 can mean you earn $3 more than you spend. A negative cycle means no shortest path exists at all, since looping keeps making it shorter.

Worked example: W3Schools — Bellman-Ford Algorithm (manual run-through, negative-cycle detection)

Floyd-Warshall O(n³)

Every pair at once — try each vertex as a possible intermediate.

Input: a distance matrix dist[][] — direct edge weights, INF where there is no edge, 0 on the diagonal. Update rule for each intermediate vertex k, for every pair (i, j):

dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])

Why it works (optimal substructure): if the shortest path from i to j passes through k, then the i→k and k→j parts are themselves shortest. In course notation, iter[k][i][j] restricts intermediates to {1..k}; the black box returns dist[][] from the n-th iteration, plus iter[][][]. Negative weights are fine, negative cycles are not. O(n³) time regardless of edge count, so it shines on dense graphs.

Worked example: GeeksforGeeks — Floyd-Warshall Algorithm (5-vertex matrix, step-by-step, code)

🌲 MST — Minimum Spanning Tree

  • Kruskal
  • Prim

Kruskal O(m log n)

Sort the edges, take the cheapest one that doesn't close a cycle.

What it is: a greedy algorithm for the minimum spanning tree of a weighted, connected, undirected graph. An MST is a spanning tree — it connects all vertices with no cycles — whose total edge weight is minimum. Kruskal makes a locally optimal choice at each step (always the cheapest remaining edge), and the Cut Property guarantees those choices build a globally optimal tree.

  1. Sort all edges by weight in non-decreasing order.
  2. Pick the smallest edge. If it forms a cycle with the edges chosen so far, discard it; otherwise include it.
  3. Repeat step 2 until the tree has V−1 edges.

Cycle test — disjoint sets (union-find): each vertex starts in its own set. find(u) returns the set's representative (with path compression); if find(u) != find(v), the edge connects two different components, so it cannot form a cycle — include it and union(u, v). If they are already in the same set, the edge would close a cycle, so skip it.

Kruskal(G):
  sort edges by weight (increasing)
  T = empty;  initialize union-find (each vertex its own set)
  for each edge (u, v) in sorted order:
    if find(u) != find(v): add (u, v) to T; union(u, v)
  return T          // |T| = n-1 edges

Runtime: O(m log m) = O(m log n) — dominated by sorting the edges; the union-find operations are nearly O(1) each. Output: edges[] — the n−1 MST edges. Reach for Kruskal when you need the list of edges (to sum weights, or to build another graph from them).

Worked example: GeeksforGeeks — Kruskal's Minimum Spanning Tree Algorithm (9-vertex illustration, DSU code)

Prim O(m log n)

Grow one tree, always adding the cheapest edge leaving it.

What it is: a greedy MST algorithm like Kruskal's, but instead of scanning all edges it grows a single tree from one starting vertex. At every step it considers all edges connecting the tree to the outside, and picks the minimum-weight one — the lightest edge crossing the cut (S, V∖S), where S is the tree so far. The Cut Property guarantees that choice is safe.

How it works — key values: maintain two sets: vertices already in the MST, and vertices not yet included. Each outside vertex v has a key[v] — the weight of the cheapest edge connecting v to the tree (∞ if none yet). Start with key 0 for the first vertex and ∞ for the rest. Then repeat: pick the outside vertex u with the smallest key, add it to the tree (recording parent[u] = the vertex that gave it that key), and update the keys of u's neighbors — if the edge u–v is cheaper than key[v], set key[v] = w(u, v) and parent[v] = u.

Prim(G, s):
  key[v] = ∞ for all v; key[s] = 0; parent[s] = -1
  T = empty
  while there are vertices outside T:
    u = outside vertex with minimum key[u]
    add u and edge (parent[u], u) to T
    for each neighbor v of u outside T:
      if w(u, v) < key[v]: key[v] = w(u, v); parent[v] = u
  return T

Runtime: O(m log n) with a min-heap holding the outside vertices by key (each edge triggers at most one key update). The simple adjacency-matrix version, which scans all vertices for the minimum key each round, is O(n²). Output: prev[] (the parent pointer of each vertex). Reach for Prim when you need the tree structure — to walk from a vertex to the root, or to find the path between two vertices in the tree.

Worked example: GeeksforGeeks — Prim's Algorithm for Minimum Spanning Tree (MST) (key-value walkthrough, code)

🌊 Max Flow

  • Ford-Fulkerson
  • Edmonds-Karp

When to use which

Ford-Fulkerson O(mC)

Keep finding augmenting paths in the residual graph until none remain.

The setup: a flow network with source s and sink t. A valid flow satisfies two constraints — capacity (0 ≤ f(e) ≤ c(e) for every edge) and conservation (inflow = outflow at every vertex except s and t). The goal is to maximize the flow value, the net flow leaving s.

Why the naive attempt fails: greedily pushing flow along any s–t path in the "available capacity" graph can get stuck below the maximum. The lecture's toy example stops at flow 10 while the true maximum is 17 — because once flow is sent, the naive graph offers no way to undo it.

Key idea — backward edges. Sending flow a → b "opens the faucet"; sending flow b → a "closes" it — i.e. decreases the a → b flow. So the residual network Gf contains, for each original edge (u, v), a forward edge with residual capacity c − f (room to send more) and a backward edge with residual capacity f (flow that can be taken back). Augmenting along s → b → a → t can then reroute earlier flow and reach the optimum.
Ford-Fulkerson(G, s, t):
  f(e) ← 0 for all edges e
  loop:
    build residual network G^f for current flow f
    find an s–t path P in G^f (BFS/DFS)
    if no such path: output f and stop
    c(P) ← minimum residual capacity along P
    augment c(P) units along P:
      forward edge (u,v):  f(u,v) ← f(u,v) + c(P)
      backward edge (u,v): f(v,u) ← f(v,u) − c(P)   # take back flow

Termination and correctness: stop when the residual network has no s–t path. That the resulting flow is a max flow follows from the max-flow = min-cut theorem — no augmenting path means the reachable set from s in Gf defines a cut whose capacity equals the flow value.

Runtime — O(mC): capacities must be integers. Each augmentation adds at least 1 unit of flow (bottleneck of integer residual capacities), so there are at most C rounds, where C is the max-flow value. Each round costs O(m): finding the path by BFS/DFS is O(n+m), and updating the residual network along a path of at most n−1 edges is O(n). Total: O(m) per round × at most C rounds = O(mC). This is pseudo-polynomial — it depends on the value C, not just the input size — which is why Edmonds-Karp (always take the shortest augmenting path, O(nm²)) exists.

Worked examples: MF1 Review Notes — naive failure, backward edges, residual network, O(mC) analysis (lecture-based)

Edmonds-Karp O(nm²)

Same paradigm as Ford-Fulkerson — but always take the shortest s–t path.

Instead of any s–t path, Edmonds-Karp (1972) always augments along the shortest path (fewest edges) in the residual network, found by BFS with edge weights ignored. That one discipline makes the s–t distance in the residual graph monotone non-decreasing, which bounds the number of rounds to at most O(mn) — so the total runtime is O(nm²). Unlike Ford-Fulkerson's O(mC), it is independent of the max-flow size, and the integer-capacity assumption is gone. Same outputs: flow[], C.

🧩 Logic

  • 2-SAT

2-SAT O(n+m)

Turn clauses into implications, then let SCC decide.

The setup: a 2-CNF formula — a conjunction of clauses, each with exactly two literals. The k-SAT dichotomy is the context: 3-SAT and up are NP-complete, but 2-SAT is solvable in linear time using the SCC black box. (Unit clauses are eliminated first: a clause (x̄1) forces x1 = False, clauses containing x̄1 are deleted, and x1 is dropped from the clauses containing it — repeat until all clauses have size exactly 2.)

The implication graph: convert logic into a graph problem. Create 2n vertices (one per literal) and 2m edges (two per clause): a clause (α ∨ β) becomes ᾱ → β ("if α is false, β must be true") and β̄ → α ("if β is false, α must be true").

The SCC condition — unsatisfiability test. A path xi ⇝ x̄i means setting xi = True forces xi = False — a contradiction, so xi cannot be True. If both directions exist, i.e. xi and x̄i lie in the same SCC, the formula is unsatisfiable. Conversely, if every variable's two literals sit in different SCCs, the formula is satisfiable — and the algorithm below constructs an assignment.

The algorithm — peel off a sink:

  1. Simplify the formula (eliminate unit clauses) so every clause has size exactly 2.
  2. Build the implication graph and find its SCCs (with topological order).
  3. Take a sink SCC S and set all its literals to True — it has no outgoing edges, so no implications need following.
  4. Its complement S̄ is a source SCC — set it to False.
  5. Remove S and S̄ (each variable's two literals disappear together) and repeat. When the graph is empty, the formula is satisfied.

Key fact — complement of a sink is a source: if no variable shares an SCC with its negation, then S is a sink SCC ⟺ S̄ is a source SCC. It rests on the claim that a path α ⇝ β implies a path β̄ ⇝ ᾱ (reverse every edge of the path using the other implication of each clause). Runtime: O(n+m), dominated by the SCC computation. Output: assignments[] or "NO".

Worked examples: GR2 Review Notes — SAT quiz, unit-clause elimination, implication graph, SCC condition, key-fact proof (lecture-based)
